# Review Axes

Диспетчер. Сам ревью НЕ делает — выбирает оси и вызывает их владельцев.
Каждая ось имеет ровно одного владельца, оси не пересекаются.

Дополнительный, on-demand инструмент. **Не заменяет** обязательный
Code Reviewer из Phase H (`docs/plans/2026-05-21-developer-agent-workflow.md`) —
тот дисбатчится на каждый PR отдельно и независимо от того, запускался ли
`/review-axes`.

## Бюджет токенов (соблюдать строго)

1. Файлы `axes/*.md` читать **только для активных осей**. Неактивная ось = файл не открывается.
2. Владельцу оси передавать **список затронутых файлов и hunks**, не «отревьюй репозиторий».
3. Тир не запускается, если предыдущий дал `MUST_FIX_PRE_MERGE`.
4. Исходники читать по hunks (`git diff -U15`), целиком — только если hunk непонятен без контекста.
5. Не пересказывать дифф в ответе. Только находки.

## Шаг 1 — собрать дифф (одна команда)

```bash
git diff --name-only $(git merge-base HEAD dev)...HEAD; git status --porcelain
```

Untracked-файлы (`??`) — тоже часть диффа: в этом репо агенты часто оставляют
новый код неотслеженным.

## Шаг 2 — выбрать оси

Ось активна, если сработал хотя бы один триггер. `correctness` активна всегда.

| Ось | Триггер (путь / содержимое) | Тир | Владелец |
|---|---|---|---|
| `correctness` | всегда | **P0** | `/code-review` |
| `persistence` | `*/migrations/*`, `models.py`, `transaction.atomic`, `select_for_update`, raw SQL | **P0** | *(inline — нет выделенного агента)* |
| `architecture` | импорт между `apps/*`, `clients/`, `eventbus/`, `events/`, новые модели, REST в Ayla | **P0** | *(inline — нет выделенного агента)* |
| `security` | `api/`, `views.py`, `serializers.py`, `settings/`, `.env*`, `permissions`, JWT/tenant/PII/consent | P1 | `/cso` |
| `tests` | `test_*.py`, `*/tests/*`, `fixtures/`, ИЛИ новый публичный код без тестов | P1 | *(inline — нет выделенного агента)* |
| `second-opinion` | дифф >300 строк ИЛИ P0 нашёл спорное ИЛИ явно попросили | P1 | `/codex` |
| `performance` | ORM в цикле, новый эндпоинт, `.filter()` внутри `for`, batch/celery-задачи | P2 | *(inline — нет выделенного агента)* |
| `docs` | `docs/**`, `CLAUDE.md`, `*.md` в корне, ADR | P2 | *(inline — нет выделенного агента)* |

`(inline — нет выделенного агента)` — на репозитории нет отдельного
sub-agent'а/skill'а под эту ось. Не пропускать ось: прочитать `axes/<ось>.md`
и пройти чек-лист самостоятельно, пометив в отчёте `(inline, владелец не установлен)`.
Если позже появится подходящий существующий агент/skill — заменить строку на
его точное имя и способ вызова, только после проверки, что он реально
вызываем в текущем runtime.

`/code-review`, `/cso`, `/codex` — существующие в этом окружении команды/skills;
их фактический input/output контракт (принимают ли они точечный список файлов
и hunks, а не «весь PR/репозиторий») не гарантирован этим документом и должен
быть перепроверен владельцем перед первым реальным использованием оси.

## Шаг 3 — прогон

Для каждого тира по порядку P0 → P1 → P2:

1. Для каждой активной оси тира: прочитать `axes/<ось>.md`, вызвать владельца
   с путями из шага 1 и чек-листом из файла оси.
2. Собрать находки в общий буфер.
3. Если в тире есть `MUST_FIX_PRE_MERGE` — **СТОП**. Вывести отчёт, оставшиеся тиры
   пометить `не запускался (блокер в тире N)`.

Оси одного тира по умолчанию идут последовательно. Параллельный прогон
субагентами — только если пользователь передал `--parallel` (в этом проекте
Agent не вызывается без явной просьбы).

## Шаг 4 — отчёт

Одна таблица, сортировка по severity:

| Ось | Severity | Файл:строка | Находка | Что делать |

Severity по рубрике проекта (`docs/plans/2026-07-02-AGENT_OPERATING_RULES.md` §C.2):
`MUST_FIX_PRE_MERGE` (блокер) · `MUST_FIX_PRE_PILOT` (до пилота) ·
`FOLLOW_UP` (issue) · `NICE_TO_HAVE`.

`MUST_FIX_PRE_MERGE` только для: эксплуатируемая уязвимость, кросс-тенантная
утечка, порча данных, необратимая миграция, обход/подделка JWT, нарушение
ADR-0009, поломка биллинга.

В конце обязательны две строки:
- `Оси активны: <список>`
- `Оси пропущены: <список> — триггеры не сработали`

Вторая строка обязательна: молчаливый пропуск оси читается как «проверено».

## Аргументы

| Вызов | Поведение |
|---|---|
| `/review-axes` | авто-выбор по диффу, тиры P0→P1 |
| `/review-axes p0` | только тир P0 (быстрый пре-коммит гейт) |
| `/review-axes persistence,tests` | точечно, триггеры игнорируются |
| `/review-axes --all` | все 8 осей, без fail-fast (перед пилотным релизом) |
| `/review-axes --parallel` | оси тира параллельно субагентами |
| `/review-axes <PR#>` | дифф берётся из `gh pr diff <PR#>` |
