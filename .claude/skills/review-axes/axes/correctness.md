# Ось: correctness

**Владелец:** `/code-review` (builtin plugin)
**Не трогает:** безопасность, БД, архитектуру, тесты — у них свои оси.

## Чек-лист

- Логика hunk'а делает то, что заявлено в описании изменения.
- Граничные значения: пусто, None, 0, один элемент, максимум.
- Ошибки: что произойдёт при исключении внутри изменённого блока.
- Регрессия: изменённая функция вызывается ещё откуда-то — новый контракт совместим?
- Мёртвые ветки, недостижимый код, забытые early-return.
- Для regex/парсинга: прогнать реальные строки, а не рассуждать о паттерне.
  Особенно русская морфология — компаунды, падежи, хвост после существительного.

## Формат находки

`файл:строка` · что сломается · конкретный вход, дающий сбой · severity.

Без воспроизводимого входа находка не считается подтверждённой — либо
дописать вход, либо пометить `PLAUSIBLE`.
