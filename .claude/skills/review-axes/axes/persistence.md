# Ось: persistence

**Владелец:** Agent tool, `subagent_type=Database Optimizer`. Этот файл
целиком идёт в промпт субагенту вместе с путями/hunks из шага 1 диспетчера.
Если тип недоступен в runtime — пройти чек-лист инлайн, пометив в отчёте
`(inline, agent-тип недоступен)`.
**Не трогает:** бизнес-логику (correctness), права доступа (security).

## Чек-лист

### Миграции
- Обратима? Если нет — явно сказано в отчёте, это кандидат в `MUST_FIX_PRE_MERGE`.
- Блокирует ли большую таблицу: `ALTER TABLE ... ADD COLUMN NOT NULL DEFAULT`,
  создание индекса без `CONCURRENTLY`.
- Партиальные unique-индексы: условие совпадает с тем, что даёт код?
  Существующие строки не нарушат ограничение?
- Data-миграция и schema-миграция в одном файле — разделить.
- Есть ли конфликт номеров миграций с параллельными ветками.

### Запросы
- N+1: `.filter()` / доступ к FK внутри цикла без `select_related` / `prefetch_related`.
- `select_for_update()` вне `transaction.atomic` — блокировка не работает.
- `select_for_update()` с nullable-join — тихо теряет строки.
- `get_or_create` / `update_or_create` без unique-ограничения на ключе — гонка.
- Индекс под фильтр существует? Для jsonb — opclass поддерживает оператор
  (`jsonb_path_ops` не индексирует `?`).

### Транзакции
- Внешний HTTP-вызов внутри `atomic` — держит соединение и откатится не полностью.
- Идемпотентность потребителей событий (ADR-0009 §5).
