# Ось: security

**Владелец:** `/cso` (gstack)
**Не трогает:** архитектурные границы (architecture), качество тестов (tests).

## Чек-лист

### Мультитенантность — приоритет №1 в этом репо
- Каждый queryset на пользовательских данных отфильтрован по тенанту.
- `tenant_id` берётся из проверенного JWT-клейма, не из тела запроса.
- Связь пользователь↔тенант подтверждена через `TenantUserRelationship`.
- Глобальный (`tenant_id=null`) путь не открывает доступ к тенантным данным.

### Вход и права
- Новый эндпоинт: `permission_classes` задан явно, не унаследован по умолчанию.
- Валидация тела запроса на сериализаторе, а не в вью.
- Внутренние эндпоинты (`/internal/`) закрыты HMAC / service-токеном.
- Массовое присваивание: `fields = '__all__'` в сериализаторе — находка.

### Секреты и PII
- Токены и ключи не в коде и не в дефолтах settings.
- Логи не пишут персональные данные и токены (`logger.info(payload)` — находка).
- Согласие 152-ФЗ: запись памяти/персональных данных гейтится согласием.
- Шифрование чувствительных полей не обойдено новым путём записи.

### Прочее
- Внешний ввод в `eval`/`exec`/шаблон/SQL-строку.
- Новая зависимость: источник, актуальность, известные CVE.
