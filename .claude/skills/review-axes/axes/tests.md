# Ось: tests

**Владелец:** Agent tool, `subagent_type=Test Results Analyzer`. Этот файл
целиком идёт в промпт субагенту вместе с путями/hunks из шага 1 диспетчера.
Если тип недоступен в runtime — пройти чек-лист инлайн, пометив в отчёте
`(inline, agent-тип недоступен)`.
**Не трогает:** корректность прод-кода (correctness) — здесь оценивается
только качество и покрытие самих тестов.

## Чек-лист

- **Сила оракула.** Тест упадёт, если сломать поведение? Ассерты на реальный
  результат, а не на `assert result is not None` / `assert called`.
- **Дыры в классах входов.** Параметризация покрывает вариации *формы*
  (пробелы, регистр), но не вариации *смысла*? Это самая частая дыра: 100
  зелёных тестов на whitespace и ни одного на фразу с дополнением.
  Выписать классы эквивалентности и отметить непокрытые.
- **Негативы.** Есть ли тесты на то, что НЕ должно срабатывать, а не только
  на happy path.
- **Изоляция.** Порядок тестов, общий state, зависимость от Redis/сети/времени.
  Тест, падающий без внешнего сервиса, — не unit-тест.
- **Фикстуры.** Счётчики и golden-файлы обновлены синхронно с кодом.
- **Тавтология.** Тест, повторяющий реализацию (тот же regex в ассерте),
  ничего не проверяет.
- **Новый публичный код без теста** — находка `MUST_FIX_PRE_PILOT` как минимум.

## Формат находки

Назвать конкретный непокрытый вход и сказать, какой тест его закрыл бы.
«Мало покрытия» без конкретного входа — не находка.
