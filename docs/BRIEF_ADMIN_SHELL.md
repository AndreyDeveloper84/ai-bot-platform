# Бриф: каркас пилотной салонной админки (DRF-1235)

**Решение владельца 07.09.2026:** строим салонную админку по макетам из Linear —
три вкладки **«Сегодня · Расписание · Ayla»**. Существующая пятивкладочная
(`День · Команда · Услуги · Чаты · Настройки`) — **временный мост**, её не ломать
и не удалять. Чего не хватает — достраиваем по ходу.

Ты строишь **только каркас**: маршруты, навигацию, три экрана-заготовки
и права. Содержимое экранов — отдельные задачи (DRF-1236, DRF-1237, DRF-1249),
их не трогай.

Макет приложен **картинкой в описании задачи DRF-1235** в Linear
(inline-изображение `uploads.linear.app`, не вложение). Достань его
инструментом `mcp__linear-api__extract_images` и **посмотри глазами**.
Ключ Linear не печатать. Если картинки в DRF-1235 нет — посмотри DRF-1236,
там макет «Сегодня» с видимой навигацией, и скажи об этом в отчёте.

**Строй по макету, а не по этому тексту.** Бриф описывает рамки; если макет
противоречит брифу — не решай сам, останови и напиши в отчёт.

## Состав работы

1. **Три маршрута** `/admin/today`, `/admin/schedule`, `/admin/ayla`
   и навигация из трёх вкладок для пилотной админки.
2. **Заготовки трёх экранов.** Не заглушки «скоро будет»: экран должен
   отрисовать свою рамку и честно показать, что данных пока нет, если ручки нет.
   Никаких обещаний того, чего бэкенд не отдаёт.
3. **Права.** Экраны доступны owner и admin. Роль ресепшн **не открывай** —
   это отдельный открытый вопрос владельца (какие ручки ей открывать), и решать
   его в этой задаче нельзя.
4. **Пятивкладочную админку не ломать.** Обе живут параллельно, пока владелец
   не скажет иначе. Существующие тесты, включая
   `App.receptionSurface.test.tsx`, должны остаться зелёными.

## Жёсткие ограничения

* **Кнопку не показывать, если сервер откажет.** Это нарушено в существующем
  коде (`AdminSalonDayScreen.tsx:109,114,125` считает доступность действий
  по жизненному циклу визита, а не по роли) — **не копируй этот приём**.
* **Телефон клиента не выводить** нигде (DRF-1039).
* **Поле «Кабинет» не рисовать**: макеты его обещают, а в `DayVisit` такого
  поля нет (`apps/admin_api/services/salon_day.py:152-167`).
* Колбэки и переходы не должны нести цену, слот или id тенанта как бизнес-правду.
* `StateError` переиспользуй — им пользуются 7 админ-экранов; не заводи свой.

## Как работать

* Ветка от свежего `origin/dev`, **свой worktree**; в чужие worktree не заходить.
* **`git stash` не использовать вообще** — стэш общий на все worktree репозитория,
  чужую работу подхватить легко.
* **Коммить промежуточное**, не копи всё в один финальный коммит.
* PR открывать **против `dev`**, не против `main`.
* Перед объявлением готовности проверь **настоящие** workflow:
  `ci` = `274201556`, `replay` = `274201559`. `ci-docs-skip` (279530142) и
  `replay-docs-skip` (279530140) сами себя отменяют, и `gh pr checks` рисует это
  как провал — не путать. В каждом обращении к `gh` передавай
  `-R AndreyDeveloper84/ai-bot-platform`, иначе из чужого каталога ответит
  другой репозиторий. Короткий SHA в `gh run list` возвращает пусто, не ошибку —
  используй полный.
* Есть страж утверждений об отсутствии: перед `assert X not in ...` нужно
  утверждение о присутствии на тех же данных, иначе `ci` красный на AST-линте.
* Секреты не печатать.
