## Правила окна

**Linear не трогать.** Мутации делает только главное окно. Находки — в отчёт и в этот файл; я заведу задачи сам.

**Пилот не менять.** `ssh taximeter@194.87.99.126` — только чтение: `docker logs`, `docker exec` для разовых замеров, `psql` на чтение. Ни пересборок, ни пересозданий, ни правки файлов **внутри контейнеров**. Один исполнитель это нарушил 02.09 — вносил файлы в работающий контейнер; больше так нельзя.

**Свои рабочие деревья** от `origin/dev`, и проверять `git log -1` после отведения: 02.09 исполнителя посадили в дерево от шестнадцатого коммита истории, и вывод был бы ложным, поверь он тому, что видел.

**Ответ — это число.** Не «похоже, узкое место здесь», а «шаг X занимает N мс, замерено так-то, повторено M раз».

## Почему это окно, а не чтение кода

Все находки 01–03.09 пришли из замеров живой системы, ни одна — из чтения:

| Находка | Как найдена |
|---|---|
| Бэкенд душит бота на слотах (429) | журналы двух контейнеров |
| Минута на первый ответ | два вызова подряд с секундомером |
| 78 пакетов мимо лока | сравнение контейнера с `uv.lock` |
| 53 с «наших» из 57 | вычитание сырого запроса из полного хода |
| Скачивание с GitHub режется | контраст `ls-remote` против `fetch` |

И наоборот: чтение кода трижды дало **неверный** диагноз (домашний каталог, прокси, диск). Поэтому здесь замер первичен, а код — только для объяснения замеренного.

## Четыре вопроса

### 1. Куда уходят 7 секунд прогретого ответа

Три секунды — модель. **Остальные четыре — наши, и они не разобраны.**

Разложить ход по шагам с метками времени: приём сообщения → определение пользователя → сохранение → передача консьержу → сборка запроса → вызов модели → отправка ответа.

Из журнала 03.09 видно, что от приёма (04:50:43) до передачи консьержу (04:50:56) прошло **13 секунд** — уже подозрительно много для мелких шагов.

**Ответ:** таблица «шаг → мс», сумма сходится с наблюдаемым.

### 2. Что лежит в 5201 токене запроса

Разобрать по частям: описание роли, память о клиенте, история, каталог, описания инструментов. Сколько токенов каждая.

Отдельно: в журнале мелькает `tiktoken not installed — history token budget falling back to…`. **Проверить, не кладём ли мы в запрос больше, чем думаем**, из-за приблизительного счёта.

**Ответ:** разбивка в токенах + что можно не класть без потери качества.

### 3. Сколько обращений на один показ расписания

Бот спрашивает слоты **по одной дате**. Посчитать: сколько специалистов × сколько дат за один показ, сколько это запросов, сколько времени.

**Ответ:** число запросов и оценка, во что превратится при запросе диапазона одним обращением.

### 4. Какие внутренние пути без своей квоты

Под `/api/v1/internal/` у части путей есть своя квота (`payment_internal`, `food_scan_internal` — 60/min), у части нет, и они падают под `anon: 30/min`. Слоты — найденный случай (DRF-1446).

**Ответ:** таблица «путь → квота или её отсутствие → зовёт ли бот пачками».


### 5. Сколько запросов к базе на один ход и на один показ расписания

Классическая причина медленного пути — сотни мелких запросов вместо одного. Отдельный запрос дешёв (замерено: 0.5 мс), но пятьсот таких дают четверть секунды, а пять тысяч — две с половиной.

**Как мерить, не трогая контур.** Расширение `pg_stat_statements` на бэкенде доступно, но **не включено**, а включение требует перезапуска базы пилота — не делать. Вместо этого считать средствами Django внутри контейнера:

```python
from django.db import connection, reset_queries
connection.force_debug_cursor = True
reset_queries()
# ... выполнить нужный путь кода ...
print(len(connection.queries))
for q in connection.queries[:20]:
    print(q["time"], q["sql"][:160])
```

Это не меняет ни настроек, ни данных: счётчик живёт в процессе и только на время замера.

**Что померить:**

- один ход разговора (приём → ответ);
- один показ расписания;
- отдельно — участок «приём сообщения → передача консьержу», где по журналу 03.09 уходит **13 секунд** ещё до модели.

**Искать не общее число, а повторы**: один и тот же запрос с разными идентификаторами, выполненный в цикле, — это и есть узкое место, которое лечится одним обращением вместо N.

**Ответ:** число запросов на каждый путь, список повторяющихся с кратностью, и оценка, сколько времени вернёт склейка.

## Чего не делать

**Не чинить.** Это окно измеряет и объясняет. Правки — отдельными задачами через главное окно.

**Не оптимизировать по догадке.** Если замер показал, что шаг занимает 20 мс, он не узкое место, даже если код выглядит плохо.

**Не смешивать с медленным диском.** Машина пилота ограничена по вводу-выводу (`w_await` 3.5 с). Часть чисел будет объясняться железом, а не кодом — **говорить об этом прямо**, иначе мы начнём чинить хостинг правками в коде.
