## 2. Решение владельца, на котором всё стоит

Прочитай **DRF-1260** целиком — там owner ruling от 23.08. Ниже главное, но не замена чтению.

### Пять ключей пилота

```
preferred_time_slots     удобное время
preferred_districts      предпочтительные районы
price_range              диапазон цены: min, max, валюта, неполные ограничения
favorite_masters         ТОЛЬКО явно названные предпочтения
diet                     полноценный домен, не регулярки
```

**Отложено, не активировать:** `busy_days`, `home_district`, `workplace_district`, `min_rating_preference`, `prefers_flexible_cancellation`.

### Главное требование: НЕ ФАБРИКОВАТЬ ФАКТЫ

Это переворачивает обычную логику извлечения. **Нормализация к известной категории запрещена, если человек её не назвал.**

```
«Я веган»                   -> diet_type=vegan
                               НЕ развёрнутый список meat/fish/dairy/eggs
«Ем всё, только мясо не ем» -> excluded_foods=["meat"]
                               НЕ vegetarian
«Не ем свинину»             -> явное ограничение, НЕ вывод о религии
«Не ем глютен»              -> явное ограничение, НЕ целиакия
«Не пью молоко»             -> явное ограничение, НЕ непереносимость лактозы
```

Хранить сказанное. Интерпретировать — политикой домена, отдельно и явно.

### Основание записи

**`provenance = user_stated` — единственное.**

```
часто выбирает вечер   !=  preferred_time_slots=evening
часто ходит к Анне      !=  favorite_masters=Anna
две недели без мяса     !=  diet_type=vegetarian
```

Вывод из поведения идёт своим путём и **в твой объём не входит**.

### Контекст сессии не есть память

«Сегодня хочу массаж в центре после шести до 3000» — текущий поиск, не запоминание навсегда. Различение делает согласие, не извлекатель.

## 3. Аллергия — отдельный периметр, и это про безопасность

```
«Не люблю орехи»           -> предпочтение, зелёная зона
«У меня аллергия на орехи» -> чувствительное, другой периметр
```

**Ты упрёшься в это с первой же фразы** — человек назовёт аллергию в том же предложении, что и питание.

**Временное правило до реализации периметра: аллергические формулировки не сохранять вовсе.** Не в `diet`, не в зелёную зону, не потерять молча. Сохранить их как предпочтение — худший из вариантов и прямо запрещено решением.

Есть открытый продуктовый вопрос, который я не додумывал: что бот **говорит**, услышав про аллергию. Промолчать — человек решит, что его услышали. Сказать «это я не запоминаю» — честно, но требует формулировки. Подними, когда дойдёшь.

## 6. Чем доказать — четыре шага, не первый

Живым проходом на пилоте:

1. человек говорит боту предпочтение -> поле в Ayla заполнено с `provenance=user_stated`;
2. «покажи, что знаешь обо мне» -> показывает **активную** память человеческим языком — без внутренней аналитики, неподтверждённых предложений, оценок уверенности;
3. человек исправляет -> старая запись уходит через supersession с `reason=changed`, новая активна;
4. «забудь всё про моё питание» -> убирает питание и **не трогает** историю записей и факты других доменов.

Все четыре. Тесты нужны, но они доказывают устройство, а не работу.
