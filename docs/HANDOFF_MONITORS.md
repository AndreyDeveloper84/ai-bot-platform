# Мониторы главного окна — готовые команды

Приложение к `HANDOFF_MAIN_WINDOW.md`. Ставить в указанном порядке: приоритет от того, что блокирует людей, к тому, что просто полезно знать.

Все — через инструмент `Monitor`. Отчётные ставить `persistent: true`; проверки CI — разовые, они завершаются сами.

---

## 1. Отчёты активных окон — САМОЕ ВАЖНОЕ

**Зачем первым.** Это единственный способ узнать, что окно-исполнитель ждёт ответа. 15.08 окно расписания простояло, ожидая ответ, который был уже написан — главное окно не увидело, что оно до него не дошло. Простаивающее окно — самая дорогая потеря в этой схеме.

Один монитор на все четыре файла сразу, чтобы не плодить наблюдения:

```bash
declare -A P; for f in REPORT_SCHEDULE REPORT_SALON_BOT REPORT_KNOWLEDGE-GAPS REPORT_DRF-1032; do P[$f]=""; done
while true; do
  for f in REPORT_SCHEDULE REPORT_SALON_BOT REPORT_KNOWLEDGE-GAPS REPORT_DRF-1032; do
    F="/c/Users/user/PycharmProjects/Ayla/docs/$f.md"
    if [ -f "$F" ]; then
      cur=$(md5sum "$F" | cut -d' ' -f1)
      if [ "$cur" != "${P[$f]}" ]; then
        if [ -n "${P[$f]}" ]; then echo "$f обновлён"; else echo "$f появился — окно стартовало"; fi
        P[$f]=$cur
      fi
    fi
  done
  sleep 30
done
```

`description`: `отчёты активных окон-исполнителей`, `persistent: true`, `timeout_ms: 3600000`.

**Если окон станет больше или меньше** — правь список в двух местах строки `for f in ...`.

## 2. Состояние пилота (бот)

Раз в пять минут. Сообщает только при изменении.

```bash
prev=""
while true; do
  out=$(ssh -o ConnectTimeout=20 -o BatchMode=yes taximeter@194.87.99.126 \
    'h=$(curl -s -o /dev/null -w "%{http_code}" -m 10 http://127.0.0.1:8014/healthz/);
     w=$(docker inspect -f "{{.State.Health.Status}}" ayla-bot-staging-web-1 2>/dev/null);
     g=$(cd /home/taximeter/ai-bot-platform-dev && git rev-parse --short HEAD 2>/dev/null);
     l=$(docker logs --since 12m ayla-bot-staging-celery-worker-1 2>/dev/null | grep -c "llm.health.alert");
     echo "healthz=$h web=$w HEAD=$g тревог_LLM=$l"' 2>/dev/null || echo "ssh_недоступен")
  if [ "$out" != "$prev" ]; then echo "Пилот: $out"; prev="$out"; fi
  sleep 300
done
```

`description`: `состояние пилота: health, web, HEAD, тревоги LLM`, `persistent: true`, `timeout_ms: 3600000`.

**Важная поправка, выученная 14.08.** Первая версия этого монитора сама дёргала прокси к OpenAI своим запросом — и дала ложную тревогу, потому что мерила холодный старт. **Так не делать.** У бота есть собственный мониторинг доступности модели (DRF-1054, задеплоен, работает, проверки каждые 5 минут). Правильно **считать его тревоги** — `llm.health.alert` в логах celery-воркера, как в команде выше. Он и точнее, и сам пишет в MAX-группу при отказе.

`HEAD` в выводе — способ мгновенно увидеть, что на пилоте развёрнуто не то, что смержено.

## 3. Состояние бэкенда

Тот же хост, другие каталог и контейнеры. Бэкенд **деплоится сам** при merge в `dev` — этот монитор единственный способ заметить, что выкладка прошла или упала.

```bash
prev=""
while true; do
  out=$(ssh -o ConnectTimeout=20 -o BatchMode=yes taximeter@194.87.99.126 \
    'h=$(git -C /home/taximeter/beautygo/dev rev-parse --short HEAD 2>/dev/null);
     w=$(docker inspect -f "{{.State.Status}}" dev-web-1 2>/dev/null);
     c=$(docker inspect -f "{{.State.Status}}" dev-celery_worker-1 2>/dev/null);
     echo "HEAD=$h web=$w celery=$c"' 2>/dev/null || echo "ssh_недоступен")
  if [ "$out" != "$prev" ]; then echo "Бэкенд: $out"; prev="$out"; fi
  sleep 300
done
```

`description`: `состояние бэкенд-стека: HEAD, web, celery`, `persistent: true`, `timeout_ms: 3600000`.

## 4. Проверки открытого PR — по ситуации, не постоянный

Ставить на время ожидания конкретного PR; завершается сам, когда проверки добежали.

```bash
cd /c/Users/user/PycharmProjects/ai-bot-platform-<нужный-worktree> || exit 1
prev=""
while true; do
  s=$(gh pr checks <НОМЕР> --json name,bucket 2>/dev/null)
  if [ -n "$s" ]; then
    cur=$(echo "$s" | python -c "import json,sys; d=json.load(sys.stdin); print(' | '.join(sorted(f\"{x['name'][:28]}={x['bucket']}\" for x in d)))" 2>/dev/null)
    npend=$(echo "$s" | python -c "import json,sys; d=json.load(sys.stdin); print(sum(1 for x in d if x['bucket']=='pending'))" 2>/dev/null)
    if [ "$cur" != "$prev" ] && [ -n "$cur" ]; then echo "PR <НОМЕР>: $cur"; prev="$cur"; fi
    if [ "$npend" = "0" ]; then echo "PR <НОМЕР>: все проверки завершены"; break; fi
  fi
  sleep 60
done
```

`persistent: false`, `timeout_ms: 3600000`.

## Общие замечания

- **Сообщать только при изменении.** Все команды выше сравнивают с предыдущим значением — иначе монитор зашумит чат и будет автоматически остановлен за избыточность.
- **`|| echo "ssh_недоступен"`** обязателен: связь периодически пропадает, и без этого монитор умрёт молча.

- **Но одной неудачи мало для тревоги.** 20.08 мониторы четыре раза за сутки сообщили `ssh_недоступен`, и все четыре раза хост был жив — обрывалась связь на стороне главного окна. Каждая такая тревога стоит ручной проверки, а главное — **приучает не верить собственным сигналам**, что хуже отсутствия монитора.

  Правильная форма — три попытки подряд, и только потом тревога:

  ```bash
  out=""
  for i in 1 2 3; do
    out=$(ssh -o ConnectTimeout=20 -o BatchMode=yes taximeter@194.87.99.126 '…' 2>/dev/null) && break
    sleep 5
  done
  [ -z "$out" ] && out="ssh_недоступен_3_попытки"
  ```

  Формулировка тревоги тоже меняется: `ssh_недоступен_3_попытки` читается как настоящий отказ, а не как «моргнуло».
- **Поле, меняющееся само по себе, отменяет детектор изменения.** 21.08 монитор пилота слал событие каждые пять минут на полном покое. Детектор изменения в нём стоял и работал — шумело поле возраста контейнера: `свежая_выкладка_4м` → `9м` → `14м`. Строка менялась каждый тик, значит «изменение» было настоящим, а новости в нём — никакой.

  **Точность поля съела тишину монитора.** Признак свежей выкладки нужен, минуты в нём — нет: заменено на `свежая_выкладка` без числа. Одно событие на выкладку вместо четырёх.

  Правило шире: **в строку, по которой сравнивают, не класть ничего, что меняется от времени** — возраст, счётчики аптайма, метки времени. Только состояние.

- **Прежде чем чинить монитор, прочитай его команду.** Там же 21.08 я остановил рабочий монитор, приняв повторы за неисправность, — хотя они были следствием только что сделанной выкладки и затихли бы сами через минуту. Пришлось поднимать заново.

  Это ровно то, чего мы требуем от исполнителей: **замер до вывода**. Монитор — такой же инструмент, как `grep` и `curl`, и врёт он так же охотно.

- **Не дублировать внутренние проверки бота внешними.** См. поправку в §2 — это уже стоило ложной тревоги.
- **Снимать мониторы перед закрытием сессии** через `TaskStop`, иначе следующее окно получит два комплекта наблюдений на один контур.

## 5. TLS и внешняя доступность

**Заведён 20.08 после трёхсуточного отказа, который не заметил ни один монитор.**

Раз в пятнадцать минут. Сообщает только при изменении состояния.

```bash
prev=""
while true; do
  out=$(ssh -o ConnectTimeout=20 -o BatchMode=yes taximeter@194.87.99.126 '
    bad=""
    for pair in "api-dev.gobeauty.site:/healthz/" "miniapp-dev.gobeauty.site:/" "proapp.gobeauty.site:/"; do
      d=${pair%%:*}; path=${pair#*:}
      code=$(curl -s -o /dev/null -w "%{http_code}" -m 15 "https://$d$path" 2>/dev/null || echo 000)
      case "$code" in 200|301|302) ;; *) bad="$bad $d$path=HTTP:$code" ;; esac
      e=$(echo | timeout 12 openssl s_client -connect "$d:443" -servername "$d" 2>/dev/null | openssl x509 -noout -enddate 2>/dev/null | cut -d= -f2)
      if [ -z "$e" ]; then
        bad="$bad $d=TLS:нет_ответа"
      else
        left=$(( ( $(date -d "$e" +%s) - $(date +%s) ) / 86400 ))
        [ "$left" -lt 14 ] && bad="$bad $d=истекает_через:${left}д"
      fi
    done
    [ -z "$bad" ] && echo OK || echo "ТРЕВОГА:$bad"
  ' 2>/dev/null || echo "ssh_недоступен")
  if [ "$out" != "$prev" ]; then echo "TLS/доступность: $out"; prev="$out"; fi
  sleep 900
done
```

`description`: `сертификаты и внешняя доступность трёх доменов`, `persistent: true`, `timeout_ms: 3600000`.

**Почему запрос идёт по публичному имени, а не на `127.0.0.1`.** Это и есть суть монитора. Все остальные проверки ходят на локальный адрес мимо TLS — поэтому 17–20 августа они показывали `healthz=200`, пока снаружи контур был недоступен: сертификат истёк, MAX не мог доставить ни одного вебхука, оба бота молчали трое суток, и узнали мы об этом от владельца.

**У каждого домена свой признак живости.** У API нет корневой страницы, и 404 на `/` там — правильный ответ. Первая редакция монитора этого не учла и подняла ложную тревогу в первую же минуту: `api-dev` проверялся тем же способом, что Mini App. Для API проверяется `/healthz/`.

Это стоит помнить при добавлении домена: **прежде чем ставить его в монитор, выясните, что у него значит «жив»** — иначе получите либо ложные тревоги, либо тишину при настоящем отказе.

**Почему порог 14 дней.** Let's Encrypt выпускает на 90 дней и продлевает начиная с 30-го дня до истечения. Тревога на 14-м означает, что автопродление пыталось и не смогло — то есть сигнал о поломке механизма, а не напоминание о сроке.

**Почему это вообще случилось.** Автопродление было сломано с самого начала: конфиги nginx на порту 80 делали безусловный редирект на https, и проверка Let's Encrypt получала SPA-фолбэк вместо токена. Три месяца молчало. Исправлено — исключение `location ^~ /.well-known/acme-challenge/` стоит до редиректа во всех трёх конфигах. **Новый домен обязан получать его до первого выпуска, а не после.**
