# Передача: окно матрицы сигналов безопасности

Составлено главным окном 08.09.2026. Окно открывается **под приём информации от владельца**: он присылает сюда решения, окно превращает их в матрицу и в контракт.

**Читать первым:** `docs/OPEN_DECISIONS.md` §40.4 п.3 (постановка), `docs/WINDOW_PATH_REGISTRY.md` (границы путей), `docs/BRIEF_TRACKS_COMMON.md` (общие правила).

---

## Зачем окно

Канон требует **четыре** состояния безопасности: `NORMAL / CLARIFY / CAUTION / STOP`. Матрицы «какой сигнал в какое состояние ведёт» владелец не давал, и без неё:

* планировочные ограничения безопасности остаются `UNKNOWN` почти целиком — план не знает, где притормозить;
* `PLAN_ENGINE_CONTRACT_v1.0.md` держит `DRAFT` (один из трёх оставшихся блокеров, после ответа на D-1 08.09).

**Это не проектирование движка.** Движок есть, он хороший. Это перевод его вердиктов в канонические состояния и заполнение единственной дыры.

---

## Что уже построено — не переделывать

`apps/orchestrator/safety/`: `pre_check.py`, `post_check.py`, `outbound.py`, `voice_check.py`, `gate.py`.

Движок **детерминированный, на регулярных выражениях, без модели**. Это его главное достоинство: он не галлюцинирует. Плюс `SafetyResult` несёт provenance — `matched_patterns` и `reason`, то есть видно, **что именно** сработало.

Замер по коду 08.09:

```python
class SafetyVerdict(str, Enum):
    ALLOW = "allow"; CLARIFY = "clarify"; BLOCK = "block"; HANDOFF = "handoff"

_VERDICT_PRIORITY = [ALLOW, CLARIFY, BLOCK, HANDOFF]   # выигрывает старший
```

Есть кризисный путь целиком: `CRISIS_HOTLINE = "8-800-2000-122"`, `CRISIS_REPLY_TEXT`, `BLOCK_REPLY_TEXT`. Есть скрининг здоровья с красными флагами — `apps/skills/health_screening/`, golden-фикстуры: температура, онемение, отдача в шею, боль в спине.

### Три расхождения с каноном

| | канон | сегодня |
|---|---|---|
| состояния | `NORMAL / CLARIFY / CAUTION / STOP` | `ALLOW / CLARIFY / BLOCK / HANDOFF` |
| `CAUTION` | обязателен | **не существует вовсе** |
| происхождение правила | `rule_id`, `policy_version` | отсутствуют |

**`CAUTION` — не переименование.** Это единственное состояние, означающее «можно продолжать, но с оговоркой». Сегодня система умеет только пропустить или остановить; **среднего нет**. Именно поэтому матрицу нельзя вывести из кода: одного столбца в коде физически не существует.

## Матрица — то, что владелец заполняет

Одна строка на сигнал. **Состояние выбирается из четырёх канонических.** Строки 1–7 — из движка; строки скрининга — отдельным блоком.

| сигнал | состояние | что Ayla делает | что Ayla говорит | можно ли записаться |
|---|---|---|---|---|
| суицидальные мысли | | | | |
| острая мед. опасность | | | | |
| насилие | | | | |
| названия лекарств | | | | |
| запрос диагноза | | | | |
| юридический совет | | | | |
| неясный мед. вопрос | | | | |
| красный флаг скрининга | | | | |

### Что означает каждое состояние — чтобы владелец выбирал осознанно

* **`NORMAL`** — разговор идёт обычным путём, сигнал не влияет ни на что.
* **`CLARIFY`** — Ayla **обязана задать уточняющий вопрос** прежде чем продолжить. Не отказ: путь вперёд есть, но через вопрос.
* **`CAUTION`** — **продолжаем, но с оговоркой**. Запись возможна, рекомендация возможна, но ответ несёт предупреждение и не подаётся как безусловный. **Сегодня этого состояния нет; оно и есть новая работа.**
* **`STOP`** — дальше не идём. Ни диагноза, ни обхода «всё равно записать», ни призыва к действию (`OPEN_DECISIONS` §…: «На STOP: нет диагноза, нет обхода „всё равно записать", нет CTA»).

### Три вопроса, без которых матрица не полна

1. **Что сильнее при совпадении двух сигналов?** Сегодня приоритет зашит: `ALLOW < CLARIFY < BLOCK < HANDOFF`, выигрывает старший. С появлением `CAUTION` порядок надо назвать заново — где он стоит относительно `CLARIFY`.
2. **`CAUTION` разрешает запись или нет?** Это разделяет его от `STOP` на практике, а не на словах.
3. **Живёт ли состояние между ходами?** Если человек упомянул красный флаг, а через три реплики просит записать — состояние ещё действует или уже нет? Сегодня проверка **на каждом входящем**, памяти между ходами нет.

## Что окно делает с полученным

1. **Матрица в `docs/OPEN_DECISIONS.md`** отдельным параграфом, дословно словами владельца.
2. **Контракт** — как отображаются четыре канонических состояния на существующие вердикты, и что делать там, где отображения нет (это `CAUTION`).
3. **`rule_id` и `policy_version`** — форма и происхождение; `SafetyResult` уже несёт `matched_patterns`, то есть половина provenance есть.
4. **Оценка в SP** — что строится на сегодняшнем движке, что требует нового.

**Кода не трогать до заполненной матрицы.** Документ — результат.

## Запреты

* **Не выводить матрицу из кода.** Код не содержит `CAUTION`; вывести его оттуда невозможно, а догадка о намерении владельца — это выдумка, и на ней сегодня уже обожглись (§66: решение владельца вывели из детали реализации).
* **Не ослаблять первый сигнал.** Принцип «пропуск — провал, ложное срабатывание — цена UX» записан автором движка и подтверждён владельцем 03.07. Уменьшать полноту ради точности — не право исполнителя.
* **Не трогать `apps/orchestrator/safety/**` без отдельного разрешения.** В реестре путей `apps/orchestrator/concierge.py` числится общим; безопасность до сегодня никто не объявлял — объяви пакет главному окну до первого коммита.
* **Не переоткрывать решённое:** DRF-1528 (`HUMAN_LOCKED`) в работу не брать.

## Правила, стоившие нам трёх суток

* **Зелёный CI доказывает отсутствие обнаруженной регрессии, а не исправление.** Нужен targeted proof: краснеет до правки, зеленеет после.
* **`pytest` врёт кодом выхода** — верить только строке `N passed / M failed`.
* **Настоящий `ci` = 274201556, `replay` = 274201559**; двойники `279530142` / `279530140` носят те же имена. Различать **только** по `workflowDatabaseId`.
* **У боевых замеров есть срок годности** — перемерять, не цитировать.
* **Не доверять именам функций и комментариям** — за трое суток двенадцать раз комментарий говорил одно, а код делал другое.
* **Локальные ветки протухли** — разведка читает `origin/dev`.
* **Работать только в своём worktree.** Общий чекаут читать можно, писать нельзя.
