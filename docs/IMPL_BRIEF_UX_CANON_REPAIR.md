## §0. Главное правило этого брифа

**Ты работаешь с единственным экземпляром канона. Резервной копии нет, истории нет.**

Всё, что ты испортишь, восстановить будет неоткуда. Поэтому **первым действием — снять копию всего каталога** куда-нибудь вне репозитория, и только потом что-либо трогать.

Это не перестраховка. Каталог `07 UX` не отслеживается git, `git log` по нему пуст: шесть контрактов на 300+ КБ существуют ровно в одном экземпляре на диске.

## §1. Что произошло

В канонических UX-контрактах русский текст превращён в нечитаемую последовательность вида `Р В Р'ВµР РЋР вЂљ`. **Английские строки целы.**

|---|---|
| **Ayla Master Operations Screen Contract.md** | **358 из 781 — 46%** |
| **Ayla Master App Information Architecture.md** | **133 из 449 — 30%** |
| Ayla Master Schedule UX Contract.md | 157 из 928 |
| Ayla Appointment Detail Screen Contract.md | 13 из 463 |
| Ayla Master Appointment Flow MVP.md | 11 из 298 |
| Ayla Master System and Recovery UX Contract.md | 11 из 415 |
| **Итого** | **683** |

Плюс единичные строки в `docs/REPLY_MASTER_SCHEDULE_MVP_UX_CONTRACT.md` и `docs/REPLY_MASTER_SYSTEM_RECOVERY_UX_CONTRACT.md`.

**Пример** (`Ayla Master Operations Screen Contract.md:386`):

```
| Service snapshot | offering/service name, duration/price snapshot only where
permitted | Appointment Contract projection | Snapshot Р В Р вЂ¦Р В Р'Вµ Р РЋР вЂљР В Р'ВµР В РўвЂ...
```

Нечитаема **колонка с ограничением**: требование видно, а условие, при котором оно действует, — нет.

## §2. Почему это срочно

Канон перестал отвечать на вопросы, ради которых существует. Конкретный случай 16.08:

Главное окно сверяло с контрактом два наблюдения с живого экрана мастера.

- **Название услуги на карточке записи** — требование нашлось (строка на английском). На этом основании приоритет DRF-1103 поднят до Urgent.
- **Чип «постоянный клиент»** — совпадений ноль. Но утверждать, что его в контракте нет, **нельзя**: он может быть в одной из 358 нечитаемых строк.

То есть по канону уже нельзя принять решение.

---

## §3. Что я проверил сам, чтобы ты не тратил время

**Наивное обратное декодирование не работает.** Проверено: цепочки `cp1252→utf-8`, `cp1251→utf-8`, `latin-1→utf-8` падают с `UnicodeEncodeError` на первом же проходе.

Из вида искажения (`Р В Р'ВµР РЋР вЂљ` — длинные последовательности вместо одной буквы) следует, что перекодирование было **многократным**, а не однократным. Одна русская буква разрослась в 6–10 символов.

**Это гипотеза, а не факт.** Установи механизм точно, прежде чем чинить: от числа проходов и точного набора кодировок зависит, восстановим ли текст вообще.

## §4. Порядок работы — соблюдать буквально

1. **Снять копию каталога** вне репозитория.
2. **Установить механизм искажения** на одной строке: сколько проходов, какие кодировки. Доказать обратимость, восстановив строку в читаемый русский.
3. **Прогнать восстановление на копии**, не на оригинале.
4. **Проверить результат человеческим чтением** — минимум по десять строк из каждого файла, включая таблицы. Автоматическая проверка «нет последовательностей `Р В`» недостаточна: она не отличит восстановленный текст от другого мусора.
5. **Назвать невосстановимое.** Если часть строк не восстанавливается — перечисли их поимённо. Честный список потерь ценнее тихой замены на приблизительное.
6. Только после этого — перенести на оригиналы.

**Не восстанавливай «по смыслу».** Если строка не восстанавливается механически, её нельзя дописать своими словами: это канон, по нему принимают решения, и выдуманное требование хуже отсутствующего. Помечай `[ТРЕБУЕТ ВОССТАНОВЛЕНИЯ АВТОРОМ]` и вноси в список.

## §5. Вторая часть: канон не в git

`git status` в `ayla-knowledge` даёт **18 неотслеживаемых записей**, и `.gitignore` их не исключает — просто никогда не коммитили.

Среди них:

- **`07 UX/`** — все шесть контрактов;
- **`00 Foundation/Ayla Development Discipline.md`** — документ инженерной дисциплины, написан 16.08;
- `00 Foundation/Canon Governance/` — стандарт ревью канона и процесс авторства решений;
- `00 Foundation/Ayla Knowledge Area Taxonomy.md`;
- `01 Product/` — принципы и карта разговорного дизайна.

Плюс **четыре отслеживаемых файла изменены и не закоммичены**, включая `Ayla Repository Responsibility Matrix` и `Ayla Domain Event Registry` — на них ссылаются брифы окон.

**Порядок обязателен: сначала кодировка, потом коммит.** Если закоммитить сейчас, искажение зафиксируется в истории как исходное состояние, и восстановить будет уже не из чего.

**Не коммить всё подряд.** По каждой группе вынеси решение: канон — в git; черновик — в git с явным `status: draft` в заголовке; мусор — назови и не коммить. Решение по спорным — за владельцем, спрашивай в отчёте.

## §6. Что вернуть до массовой правки

1. **Механизм искажения**, доказанный на одной строке: сколько проходов, какие кодировки, восстановленный текст.
2. **Оценка обратимости**: сколько из 683 строк восстанавливается, сколько нет.
3. **Разбивка 18 неотслеживаемых записей** на канон, черновик и мусор — с обоснованием по каждой.

Дальше действуй без ожидания, если блокера нет.

## §7. Границы

- **Не менять содержание контрактов.** Задача — восстановить текст, а не улучшить его. Любое желание уточнить формулировку — в отчёт, не в файл.
- **Не трогать `docs/` кроме двух названных файлов.**
- **Не создавать новых контрактов** в рамках этой задачи.
- **Ничего не удалять** без явного согласования, даже если выглядит мусором.

## §8. Смежное, что тебе стоит знать

По ходу выяснилось, что **салонной админской поверхности контракта нет вовсе** — все шесть документов про мастера. Одиннадцать админских экранов написаны без контракта, и окно салонной админки сейчас их измеряет вслепую.

**Это следующая задача, но не эта.** Сначала восстанови существующее — иначе новый контракт ляжет рядом с нечитаемым, и мы получим два источника вместо одного.
