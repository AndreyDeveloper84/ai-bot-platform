# Замер: дневник без анкеты — где анкета сегодня блокирует, где норма показывается вместо `NOT_CONFIGURED`

**Решение:** §6 свода владельца от 11.09.2026 (`docs/ayla-owner-decisions-2026-09-11.md`), OD-NUT-1.
**База:** бот `origin/dev` = `db49a65ee01dd82a35903d5019078e3ec8bfb7e9`; каталог читался на `e26e8731`
и по ветке #332 (`85e666fa`).
**Дата:** 11.09.2026. **Кода здесь нет.**

**Что требует §6, дословно по пунктам, против которых мерилось:**

```
без анкеты ДОСТУПНО     добавление еды текстом/голосом/фото; просмотр, правка,
                        удаление своих записей; фактические значения;
                        предложение настроить ориентиры
до настройки СКРЫТО     норма калорий; «осталось»; БЖУ и вода; оценки
                        «мало/много/перебор»; прогноз веса; персональный план
неизвестные нормы       NOT_CONFIGURED, а не ноль
анкета                  запрашивается по функции, не на входе
дневник                 не передаётся салону/мастеру
```

## §0. Итог одним экраном

```
мест, где анкета/отсутствие профиля СУЖАЕТ дневник                    1   (A1)
мест, где вход в дневник закрыт НЕ анкетой, а другим                   3   (A2–A4)
мест, где число неизвестного происхождения показывается как норма      2   (B1, B2)
мест, где ноль подменяет отсутствие на границе                        1+3 (B3; B4 смежное)
мест, где «осталось»/оценка считается — и все под сторожем             5   (C1–C5)
состояние NOT_CONFIGURED в коде питания                                0   (D)
```

Состояние заметно лучше замера 10.09: просмотр дневника без профиля **работает**, отсутствие
ориентира на границе **доезжает отсутствием** (#1527), Мини-апп **различает** «цель есть» и
«цели нет». Осталось одно настоящее сужение, одно массовое показывание чисел без происхождения
и отсутствующее состояние.

## §1. A — где анкета блокирует или сужает дневник

### A1. Без профиля единственный чип дневника — «Пройти анкету» — СУЖЕНИЕ

```
apps/orchestrator/personal_surface.py:557-559
    if profile is None:
        return [dict(CHIP_ANKETA)]
    return [dict(CHIP_WATER)]
```

Докстринг говорит прямо: «Without a profile the anketa IS the next step». §6 говорит обратное:
без анкеты доступно добавление, а анкета запрашивается по функции. Человек без профиля видит
свои записи (это работает, `:482-486`), но единственное предложенное действие — анкета. Вода,
которую он мог бы записать одним тапом, не предлагается.

Это не запрет — записать воду фразой можно, — но **поверхность ставит анкету на место
действия**, и это ровно «запрашивается на входе», а не «по функции».

Текст рядом — `NO_PROFILE_TEXT = "Норм пока нет — я ещё не считала их для тебя."` (`:240`) —
§6 соответствует: это «предложение настроить ориентиры», без числа и без упрёка.

### A2. Текстовый ввод еды — не гейт, а ОТСУТСТВИЕ функции

```
apps/skills/food_clarify/skill.py:41-44
    DIARY_PROMPT = "📸 Скинь фото блюда — посчитаю калории и БЖУ.
                    Через текст пока не умею распознавать (это в работе)."
```

Анкета тут ни при чём: пути нет ни для кого. §6 требует текст и голос; это объём **DRF-1329
D-б** (разбиение в `docs/BREAKDOWN_DRF1329_FOOD_DIARY.md`), не этого среза. Голосового приёма в
боте нет вовсе — померено там же.

### A3. Фото — закрыто флагом, не анкетой

`FOOD_PHOTO_SCAN_ENABLED=false` на пилоте; §138 назвал состояние `ЗАПЕРТО` и условие включения.
Решение владельца, не предмет §6.

### A4. Пункт меню — согласие `HEALTH`, не анкета

```
apps/skills/menu/marketplace.py:145-146   без HEALTH → cb:health:need:food_diary
apps/orchestrator/personal_surface.py:364 показ дневника — PERSONAL_DATA (152-ФЗ, ADR-0011)
```

Оба — согласия, не анкета. Расхождение, записанное 10.09 (IV.2.5: два гейта на одну
поверхность, отказной текст говорит «дневник не работает», а он работает по фразе), **живо**.
§92 «отказ не закрывает дневник» — смежный предмет, здесь только назван.

### Что НЕ блокируется — проверено

* **Каталог не требует профиля для записи.** `nutrition/views.py`, `food_log_service.py`,
  `water_service.py` — ни одного `NutritionProfile.objects.get`/`get_object_or_404` на путях
  записи еды и воды. Положительный контроль: `WaterLog.DoesNotExist` в `views.py:617` тем же
  поиском находится.
* **Просмотр без профиля работает** — `personal_surface.py:482-486`: отчёт рендерится, к нему
  добавляется `NO_PROFILE_TEXT`.
* **Мини-апп читает дневник без профиля** — `wellness/today` отдаёт факт, ключи целей опускает.

## §2. B — где число показывается вместо `NOT_CONFIGURED`

### B1. `unknown_legacy` печатается числами — ГЛАВНОЕ, 6 из 6 профилей пилота

```
apps/orchestrator/personal_surface.py:259-260
    #: ``unknown_legacy`` (строки до очистки) и ``ayla_calculated`` /
    #: ``user_entered`` его не получают: у них ориентиры печатаются числами.
apps/orchestrator/personal_surface.py:496-497
    * ``"unknown_legacy"`` / ``"ayla_calculated"`` / ``"user_entered"`` —
      numbers are still printed, nothing to explain → no tail;
apps/orchestrator/personal_surface.py:261   _TARGETS_SOURCE_NONE = "none"   ← единственное «нет»
```

Бот считает «ориентира нет» **только** при `source == "none"`. `unknown_legacy` — «происхождение
не сохранялось» — трактуется как «есть», и числа уходят человеку: «Белки: 61 из 95 г».

**На пилоте это все шесть профилей** (замер 10.09 и 11.09: `targets_source=unknown_legacy` 6/6;
у двух ориентиры выведены от подставленных 70 кг, `weight_kg IS NULL`). §6: «неизвестные нормы
имеют `NOT_CONFIGURED`». §103: «уже рассчитанный ориентир нельзя показывать как актуальный без
происхождения». Оба нарушаются на каждом из шести, каждый день, пока не отработает команда
очистки из #332 (каталог) — а она не слита и не запущена.

**Следствие:** `unknown_legacy` обязан читаться как `NOT_CONFIGURED` **в боте, сейчас**, а не
ждать, пока каталог переведёт строки в `none`. Иначе исполнение §6 зависит от очерёдности чужих
запусков — а это очерёдность, не сторож.

### B2. Тот же `unknown_legacy` идёт в вечерний отчёт и в реплику коуча

```
apps/nutrition_proactive/render.py:137-140   _macro_line(..., _target(profile, "protein_g"))
apps/nutrition_proactive/render.py:186-204   goal_remark: «меньше нормы из профиля на N г»,
                                             «Калорий вышло на N ккал больше нормы»,
                                             «День уложился в нормы из твоего профиля»
```

`render_daily_report` не смотрит на `targets_source` вовсе — берёт `profile.protein_g` и печатает.
Для `unknown_legacy` это число есть. Экспозиция сегодня **ноль**: вечерний отчёт закрыт
`NUTRITION_PROACTIVE_ENABLED=false` + `DRY_RUN` (замер 10.09 IV.2.9). Механизм открыт.

### B3. Ноль как отсутствие на границе — три поля тела

```
apps/integrations/ayla/nutrition_client.py:759-761
    age=int(body.get("age") or 0),
    height_cm=int(body.get("height_cm") or 0),
    weight_kg=int(body.get("weight_kg") or 0),
```

Не нормы, но тот же класс: после #327/§120 `weight_kg` у четырёх профилей станет `NULL`, бот
прочитает `0`. Ориентиры (`:784`) через `_target_or_none` уже `int | None` (#1527); входы — нет.
Смежное, названо.

### B4. `render.py` работает по конвенции «0 = нет», не по состоянию

```
apps/nutrition_proactive/render.py:269-270
    def _target(profile, field) -> float:
        return float(getattr(profile, field, 0) or 0) if profile is not None else 0.0
apps/nutrition_proactive/render.py:288-290
    if target: ... "из N" ... else: без "из"
```

`None` → `0.0` → «нет». Пользователю не видно — `_macro_line` ноль не печатает. Но это ровно
вариант B из §103, который владелец отверг: ноль несёт два смысла. Через один рефакторинг кто-то
напишет `if target is not None` и напечатает «из 0 г». Смежное, дешёвое.

### Где ноль НЕ течёт — проверено

* `nutrition_client.py:225, 269-274, 326` — ориентиры и `norm_ml` типизированы `int | None`.
* `miniapp_api/views.py:2954, 3043, 3078-3094, 3226-3236` — `or None`, ключ опускается.
* Мини-апп `CustomerWellnessDashboardScreen.tsx:812-826, 846-863` — `caloriesTargetKnown`,
  процент только при `caloriesTarget > 0`, иначе «Питание: N ккал» без «из».

## §3. C — где «осталось» и оценки считаются, и что их держит

| # | где | что считает | сторож |
|---|---|---|---|
| C1 | `render.py:191-192` | «До нормы воды осталось N мл» | `water.norm_ml` истинно |
| C2 | `render.py:194-201` | «больше нормы на N ккал» — оценка «перебор» | `summary.calories_goal` истинно |
| C3 | `render.py:203-204` | «День уложился в нормы» — оценка | `summary.calories_goal` истинно |
| C4 | `render.py:229-233` | напоминание о воде «из N», «ещё M» | `if not water.norm_ml: return ""` + отправитель не доходит |
| C5 | `personal_surface.py:537-544` | «% от твоей нормы», «дней ниже нормы» | `pct is not None`; процент считает каталог |

Все пять под сторожем на **наличие числа**. Ни один не под сторожем на **происхождение** числа.
Для `unknown_legacy` все пять сработают и напечатают оценку от ориентира без происхождения —
«мало», «перебор», «уложился». Это пункт §6 «до настройки скрыты оценки», и он держится сегодня
не сторожем, а тем, что вечерний отчёт выключен (B2). C5 живой: «что за неделю» отвечает на
пилоте.

## §4. D — состояния `NOT_CONFIGURED` не существует

```
grep NOT_CONFIGURED по apps/ (py, ts, tsx)   1 попадание —
    apps/orchestrator/decision_readiness/shadow.py:206, другой предмет (флаги DRE)
```

В контуре питания такого состояния нет ни в DTO, ни в рендере, ни в контракте Мини-аппа.
Отсутствие сегодня выражается тремя способами, и они не сведены:

```
каталог → бот        targets_provenance.source ∈ {none, unknown_legacy, ayla_calculated, user_entered}
бот внутри           ProfileResponse.daily_kcal: int | None  +  _TARGETS_SOURCE_NONE == "none"
бот → Мини-апп       ключ calories_target опущен
```

Три представления одного факта, и правило «что считать настроенным» живёт в одном месте —
`_targets_cleared`, — которое знает про `none` и не знает про `unknown_legacy`.

## §5. Что из этого следует для PR — форма, не оценка

```
1  NOT_CONFIGURED как состояние на DTO: настроено ⇔ source ∈ {ayla_calculated, user_entered};
   всё остальное — включая unknown_legacy и пустую строку — не настроено
2  ориентиры читаются как None, когда состояние «не настроено», ОДИН РАЗ на границе
   (nutrition_client), чтобы все поверхности получили одно и то же
3  чипы без профиля: вода + предложение настроить, а не одна анкета (A1)
4  render.py: _target → None, _macro_line по `is None` (B4) — снять конвенцию нуля
5  сторож: профиль unknown_legacy с числами 95 / 1850 / 2100 → ни одно из них не
   встречается ни в дневном отчёте, ни в ответе поверхности, ни в реплике коуча;
   положительная стража — тот же профиль как ayla_calculated печатает все три
```

Пункт 5 — предмет. Без него пункты 1–4 — верный код без доказательства, и через полгода
кто-то добавит четвёртую поверхность, которая читает `profile.protein_g` напрямую.

**Границы.** `apps/skills/nutrition_anketa/**` не трогается — граница объявлена ayla-a3 (§5 свода), ответ на момент записи не получен.
Текст для `unknown_legacy` («ориентиры посчитаны до того, как мы начали хранить их
происхождение, и не показываются») — формулировка исполнителя, выносится владельцу так же, как
`NO_TARGETS_TEXT` до неё.

## §6. Чего не мерил

1. **Живой контур.** Числа пилота (6/6 `unknown_legacy`, 2 с `weight_kg IS NULL`) — цитаты
   замеров 10.09 и 11.09 главного окна, не мои. Срок годности у них есть.
2. **Прогон тестов.** Ни один вывод не опирается на прогон.
3. **`nutrition_coach` и `wellness_proactive`** — читают ли ориентиры для триггеров; на 10.09
   реплики коуча были без чисел (I.1.5), сегодня не перепроверял.
4. **Сторону каталога после #332** — что он присылает в `norms` для `unknown_legacy` до
   команды очистки; читал по коду ветки, что числа остаются.
