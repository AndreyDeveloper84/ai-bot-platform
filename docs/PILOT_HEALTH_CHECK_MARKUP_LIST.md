# Простановка признака здоровья: список решений для салона

**Составлено** 09.09.2026, окно матрицы готовности. **Только чтение — ничего не проставлено.**

Основание: решение владельца §90 («третий вариант») — после слияния PR-A и PR-B поднять
`SalonService.requires_health_check` **явным решением салона**, а не массовым `UPDATE`.
У этого значения обязан быть автор, дата и причина, иначе выдумка кода заменится выдумкой
разработчика.

---

## Сколько решений на самом деле

```
активных рёбер (мастер × услуга) : 95
различных услуг под ними          : 56     <- столько решений принимать человеку
услуг салона всего                : 58     (2 без активных рёбер)
```

**Решений 56, а не 95.** Признак живёт на услуге салона, а рёбра — на паре
«мастер × услуга»: одну услугу выполняют до трёх мастеров. Разница существенна для того,
кто будет это делать.

## Канонический каталог этот вопрос закрыть НЕ может

```
шаблонов в каноническом каталоге : 1223, из них с гейтом: 102

из 56 услуг салона:
  имя в точности совпало с гейтованным шаблоном : 0
  имя в точности совпало с шаблоном без гейта   : 8
  точного совпадения имени нет                  : 48
```

**Сорок восемь из пятидесяти шести не имеют в каноническом каталоге даже однофамильца.**
Значит подсказать ответ из каталога нельзя — ни автоматически, ни человеку «по аналогии».
Это же, попутно, объясняет, почему у салона не размечена ни одна услуга: сопоставлять
оказалось не с чем. Материал к OD-PILOT-2 («чем является каноническая услуга»).

Совпадение имён само по себе связью не является — имя не доказывает происхождения.
Восемь совпадений приведены как повод посмотреть, а не как ответ.

## На что смотреть в списке

Состав нетипичен для «формальности»: лазерная эпиляция (18 позиций), пилинги,
карбокситерапия, RF-лифтинг, УЗ-кавитация, чистки лица, детский массаж, лимфодренаж.
Это категории, где противопоказания существуют и где честный ответ салона вполне может
быть **«да, нужен скрининг»**. Список не следует считать пачкой отказов, которую надо
проштамповать `False`.

Услуга, про которую ответа нет, **остаётся `NULL` и уезжает оператору** — это законный
запасной путь, а не провал.

**Порядок (владелец, §90):** слить A+B → дождаться синхронизации → перемерить по критерию
трёх чисел (реестр §27.5) → **и только потом** проставлять. Шаг простановки без шага
перемера — это заплата на дыру, существование которой не подтверждено.

**Как проставлять:** через админку салонной поверхности, чтобы остался `LogEntry` с автором
и временем. Массовый `UPDATE` из консоли обесценивает решение целиком.
