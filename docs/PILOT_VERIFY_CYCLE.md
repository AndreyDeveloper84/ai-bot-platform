# Часть 1. Как сделать человека мастером

## Что должно быть готово

`SITE_DOMAIN` задан. **Проверено 30.08**, значение `https://miniapp-dev.gobeauty.site`.

Это не бэкенд-хост. Три хоста легко перепутать, и код прямо предупреждает:

| хост | что это |
|---|---|
| `api-dev.gobeauty.site` | бэкенд Django. На `/onboarding/master` отдаёт **404** |
| `miniapp-dev.gobeauty.site` | SPA миниаппа. **Сюда ведёт ссылка приглашения** |
| `dev.gobeauty.site/api/v1` | то, с чем говорят мобильные приложения |

Маршрут `/onboarding/master` — **клиентский**, его знает только SPA.

## Приглашение

```
POST /api/v1/admin/masters/invite
{
  "name": "...",
  "contact_method": "...",
  "contact_value": "...",
  "services": [<uuid>, ...],
  "schedule_preset": "default_mon_fri_10_19" | "none",
  "mode": "invite" | "catalog_only"
}
```

Ответ несёт `invite_token`, `invite_expires_at`, `max_dm_delivery`, **`fallback_link`**.

## Два канала, и один из них сегодня не работает

**Личное сообщение в MAX** — бот пишет человеку сам, с диплинком. Работает, **если
известен его чат в MAX**.

**Ссылка-запасной путь** — `https://miniapp-dev.gobeauty.site/onboarding/master?token=…`

> **`contact_method="max_phone"` отложен: перевода «телефон → чат» у нас нет.**
> Ответ вернёт `max_dm_delivery="skipped"`, и **ссылку придётся отправить руками**.

Практический вывод: **обычному человеку сегодня ссылку отправляете вы сами** — любым
мессенджером. Токен живёт **7 дней**.

## Чего в этом пути ещё не проверял никто

Ни один живой человек не проходил его до конца. Приглашение, переход по ссылке,

Это главный незакрытый замер пилота.

# Часть 2. Полный цикл проверки изменений

## Порядок

**1. Смержено ли — по `mergedAt`, не по молчанию.**

```
gh pr view <N> --repo <repo> --json state,mergedAt,mergeCommit
```

**2. Есть ли миграции.**

```
git diff --name-only <было> origin/dev -- '*/migrations/*.py' | grep -v __init__
```

**3. Забрать код на хост.**

```
ssh taximeter@194.87.99.126
cd /home/taximeter/ai-bot-platform-dev && git pull --ff-only origin dev
```

**4. Миграции — до перезапуска.** `migrate --check` возвращает `0`, если применять нечего.

**5. Перезапуск — и здесь две разные операции, их путают.**

*Изменился только код* — хватит перезапуска:

```
docker compose -p ayla-bot-staging restart web worker shadow-worker celery-worker celery-beat
```

*Изменилось окружение или зависимости* — нужно **пересоздание**, и обязательно с
полным набором файлов:

```
docker compose -p ayla-bot-staging \
  -f docker-compose.yml -f docker-compose.staging.yml -f docker-compose.staging.local.yml \
  up -d --no-deps --force-recreate web worker celery-worker celery-beat shadow-worker
```

> **Ловушка 30.08.** `restart` работает по контейнерам, `up` — по определениям служб и
> читает **другой набор файлов**. `up` без `-f …` ответил `no such service: celery-worker`
> и **тихо ничего не сделал**. Набор файлов надёжнее всего спросить у самого контейнера:
> ```
> docker inspect ayla-bot-staging-web-1 \
>   --format '{{index .Config.Labels "com.docker.compose.project.config_files"}}'
> ```

*Изменился `uv.lock`* — нужна **пересборка образов**: они собираются на хосте из
`Dockerfile`. Перезапуск поднимет старый образ, и обновление зависимости **не доедет**.

**6. Миниапп — собирается отдельно, скрипта нет.**

nginx раздаёт `apps/miniapp/dist` **из той же рабочей копии**, куда сделан `git pull`.

```
export NVM_DIR="$HOME/.nvm"; . "$NVM_DIR/nvm.sh"; nvm use 22
cd /home/taximeter/ai-bot-platform-dev/apps/miniapp && npm ci && npm run build
```

**Node 22 через nvm обязателен** — системный 16, Vite на нём не соберёт.

> `git pull` обновляет **исходники** миниаппа, но не то, что видят люди.
> Между `pull` и сборкой хост отдаёт старую страницу поверх нового бэкенда.

## Как проверять, что доехало

**Никогда — по коду возврата.** 29.08 выкладка дала четыре нулевых кода подряд, и
**ни один не был про миниапп**.

**Бэкенд — интроспекцией живого процесса:**

```
docker compose -p ayla-bot-staging exec -T web python manage.py shell -c "
import inspect; from apps.<модуль> import <объект>
print('<признак правки>' in inspect.getsource(<объект>))
"
```

**Миниапп — сравнением отданного с деревом:**

```
curl -s https://miniapp-dev.gobeauty.site/ | grep -oE 'assets/index-[A-Za-z0-9_-]+\.(js|css)'
ssh … 'ls .../apps/miniapp/dist/assets/ | grep -E "^index-"'
```

Хеши обязаны совпасть. `Last-Modified` в заголовке показывает дату сборки — 29.08
он показывал позавчерашнюю, и это был **единственный признак** неполной выкладки.

**Переменные окружения — `printenv` в процессе**, плюс `manage.py check`: он
жалуется человеческим языком и называет правильное значение.

# Часть 3. На что смотреть всегда

Один класс дефектов дал 29.08 шесть независимых случаев.

> ## Пустой результат неотличим от работающей функции.

| где | как выглядело |
|---|---|
| подметание ПДн | **39 зелёных на данных с настоящей утечкой** — фикстура протухла, ответ пуст |
| фикстуры кабинета | строили форму, которой прод не производит; дефект пережил **три ревью** |
| контрактный тест | маршрут «покрыт» — **недостижимым кодом** |
| golden-фикстура анкеты | не исполнялась против живого кода никогда: расхождение в **одной букве регистра** |
| `settings/base.py` | нет `POSTGRES_HOST` → **молча SQLite**; нет `REDIS_URL` → **молча localhost** |
| `ruff format` без аргументов | развернулся на **весь репозиторий**, 50 файлов |

## Четыре правила

**1. Отрицательному утверждению нужна положительная стража на тех же данных.**
«Здесь нет телефона» без «здесь вообще что-то есть» — не проверка, а надежда.

**2. Авторитет — `conclusion` прогона.** Не длительность, не цвет, не отчёт исполнителя.
Локальная краснота о ветке не говорит: 29.08 трижды объявляли `dev` сломанным, и все три
раза это была своя среда.

**3. Комментарий в коде протухает как тикет.** Где посылку можно проверить прогоном —
читать про неё нельзя. `ci.yml` уверял, что три теста падают; прогон дал 41 passed,
починка была десятью днями раньше.

**4. Перед задачей старше недели — замерить посылку.** Из 97 задач **41 % описаний не
соответствовали коду**.

## Что мерить на живом пилоте — и чего это уже стоило

Замеры, которые нельзя заменить чтением кода. Каждый из них 29–30.08 **отменял вывод,
сделанный по коду**:

```
зеркало броней 27 : BookingRequest 9   → мастер видел треть клиентов
Service (легаси) = 0                    → отзыв невозможно сохранить, отзывов 0
ClientGoal = 0                          → «не разрешилось» — норма для 100 %, не край
GoalOption 7, связей 20, но 2 цели → 0 мастеров из 9
BOOKING_VIA_AYLA_REST = true            → страшный сценарий закрыт флагом
GOAL_RESOLUTION_ENABLED не задан        → за флагом не было подключения вовсе
```

**Правило:** флаги и наполнение таблиц живут на хосте, а не в репозитории. Вывод о
поведении пилота, сделанный без запроса к нему, — гипотеза.
