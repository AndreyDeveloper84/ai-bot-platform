## 1. Общая схема

```
вебхук MAX ─► журнал ─► очередь ─► handler
                                     │ is_voice_only(event)?      ← заглушка DRF-1939, уже в dev
                                     ▼
                         voice_turn.resolve(event)                 ← НОВОЕ, одна точка входа
                           ├ флаг выкл.            → отказ voice_disabled (текст заглушки, байт в байт)
                           ├ audio.download(url)   → байты | отказ voice_too_large / download_failed / unsupported_format
                           ├ speech.transcribe()   → Transcript | отказ voice_empty / unrecognized / provider_unavailable / too_long
                           └ normalize_numbers()   → «триста грамм» → «300 грамм»
                                     ▼
                  dataclasses.replace(event, text=…, attachments=[без audio])
                                     ▼
              дальше обычный текстовый ход: record_message → evaluate_inbound → дневник → консьерж
```

Принцип из ТЗ: после подстановки — **ни одного `if voice`**. Единственное отличие хода — пометка канала у `Message`.

## 2. Нарезка на PR (каждый — в `dev`, за флагом, поведение при выключенном флаге не меняется)

### PR 1 — скачивание аудио: `apps/channels/max/audio.py`

- По образцу `photo.py`, **без переноса его имён** (тесты `photo.py` патчат `apps.channels.max.photo.socket/.httpx` — §5.4 отчёта): общие части вызываются из `photo`, новое — в `audio`.
- `extract_first_audio(attachments) -> AudioRef | None`: `type == "audio"`, берём `payload.url` и `payload.id` (по живому замеру `id` есть).
- `download_audio(url) -> bytes`: только https, та же SSRF-проверка, потоковый лимит **5 МиБ** (замер: 4 КБ/с → 5 МиБ ≈ 20 мин, с запасом на лимит 120 с), **общий** дедлайн 8 с на всю загрузку (у `photo.py` таймаут на операцию — это пробел, здесь закрываем `time.monotonic`-бюджетом).
- Проверка формата по первым байтам (`OggS`), а не по расширению: замер — `audio/ogg`, opus. Иное → `voice_unsupported_format`.
- Исключения именованные (`AudioTooLargeError`, `AudioDownloadError`, `AudioFormatError`); в логах только hostname.
- **Тесты:** SSRF (частные адреса, не-https), превышение лимита на середине потока, дедлайн, не-ogg, caplog без URL. Сеть не используется.
- Вне этого PR: вызов из handler.

### PR 2 — распознавание: `apps/speech/`

- `apps/speech/types.py`: `Transcript(text, duration_s, provider, model)`, `SpeechRefusal(code)` с кодами из таблицы ТЗ.
- `apps/speech/base.py`: протокол `SpeechProvider.transcribe(audio: bytes, mime: str) -> Transcript | SpeechRefusal`. **Никогда не бросает** (иначе ключ идемпотентности занят, а человек без ответа).
- `apps/speech/providers/openai_stt.py`:
  - клиент как в `apps/llm/providers/openai_provider.py` (тот же `OPENAI_API_KEY`, `OPENAI_PROXY`, `DefaultAsyncHttpxClient`/синхронный аналог — уточнить при реализации, какой контекст у handler);
  - `model` из настройки `VOICE_STT_MODEL` (по умолчанию `gpt-transcribe`), `language="ru"`, `temperature=0`, файл как есть (`voice.ogg`, MAX отдаёт ogg/opus — принимается без перекодировки, проверено);
  - таймаут **15 с**, повторов **0** у SDK (`max_retries=0`) — замер: норма 1–2 с, зависший запрос висит до упора; одна своя повторная попытка только если осталось ≥ 6 с общего бюджета;
  - `AuthenticationError`/`RateLimitError`/таймаут/сеть → `voice_provider_unavailable`; пустой текст → `voice_empty`.
- `apps/speech/providers/fake.py` — для тестов и локальной работы; провайдер выбирается настройкой `VOICE_STT_PROVIDER` (`openai` | `fake`).
- `apps/speech/numbers.py` — **K15**: «триста» → «300», «двести пятьдесят» → «250», «ноль целых три десятых» → «0,3», «полтора» → «1,5». Только количественные числительные рядом с единицами/в свободной позиции; **не трогаем**: «один раз», «в первый», «на три часа дня» → оставить проверку на наборе стенда, чтобы не сломать время записи («на 15:00» бот понимает, «на 3 часа дня» — проверить, что лучше). Таблица случаев — в тестах, набор из `phrases.json` стенда (d01–d12, b01, b08). Живой замер 21.09 подтвердил оба случая: «триста грамм борща» и «на три часа дня» / «на десять утра» приходят словами — время записи входит в нормализацию.
- Длительность: из ответа провайдера нет → считаем по ogg-страницам (granule position последней страницы / 48000) **до** вызова провайдера; больше лимита → `voice_too_long` без траты денег.
- Метрика: счётчик вызовов, секунд аудио, отказов по кодам, задержка (по образцу метрик `apps/llm`, найти при реализации). Потолок минут в месяц — настройка `VOICE_STT_MONTHLY_MINUTES_CAP` (0 = без потолка); при исчерпании → `voice_provider_unavailable` с отдельной причиной в метрике.
- **Тесты:** провайдер с подменённым клиентом (сеть не используется — сторож `test_vendor_sdk_isolation` учесть), каждый отказ, нормализация чисел (таблица), caplog без текста расшифровки.
- Сторожа: `import_boundaries` — `apps/speech` не импортирует `channels`/`orchestrator`; SDK `openai` импортируется только внутри провайдера.

## 3. Однопоточный потребитель

Факт: `apps/workers/consumer.py` обрабатывает события по одному; внутри хода уже сегодня выполняются LLM-вызовы с таймаутом 30 с (`LLM_REQUEST_TIMEOUT_S`). Голосовой ход добавляет к этому до 20 с в худшем случае и ~1,5 с в типичном (замер §2.5 отчёта).

Решение для этапа 1: **синхронно, с жёстким общим бюджетом 20 с**. Вынос распознавания в отдельного воркера/очередь меняет архитектуру приёма и идемпотентность — это отдельная задача не этого эпика; фиксирую как риск и вопрос главному окну. Метрика задержки голосового хода покажет, нужно ли.

## 5. K19 — варианты ответа (нужен выбор владельца)

Причина: в `apps/orchestrator/safety/pre_check.py:124` исключение гиперболы записано как `\bумираю\b(?!\s+(как\s+)?хочу)` — допускает между словами только пробел. «Умираю, хочу кофе.» с запятой под исключение не попадает → HANDOFF. Так же ведёт себя и **набранный** текст с запятой — это не дефект голоса, голос его только делает частым (OpenAI ставит знаки всегда).

| Вариант | Что делаем | Плюсы | Минусы |
|---|---|---|---|
| **А. Чинит окно safety** | В регулярке исключения разрешить знаки: `(?![\s,…—-]+(как[\s,]+)?хочу)`. Одна строка + тесты в `test_gate.py` | Исправляет причину; чинит и печатный текст; паритет «голос = текст» сохраняется полностью | Чужая зона: нужен их PR и ревью; срок не наш |
| **Б. Гейт получает копию без знаков** | В `voice_turn` для голосового хода в `evaluate_inbound` уходит текст без пунктуации; в `Message` и консьерж — оригинал. Настройка `VOICE_GATE_STRIP_PUNCT` | В наших руках, 10 строк. **Замер 20.09 на 196 расшифровках OpenAI: ложных стопов 0/140 (было 6), S1/S2 удержано столько же — 24/24 и 22/24, S1 в монологах 4/4** | Голос и текст проверяются по-разному → паритет safety нарушен формально; если детектор когда-нибудь начнёт опираться на знаки — разойдёмся молча |
| **В. Ничего не делаем в пилоте** | Оставляем как есть, ложные HANDOFF считаем метрикой | Ноль изменений safety | Каждая «умираю, хочу…» уходит оператору как кризис; человек вместо ответа получает кризисный текст |

**Рекомендация: А, а до него — Б под настройкой.** PR 3 делает Б выключаемым одной переменной; когда safety вольёт А — `VOICE_GATE_STRIP_PUNCT=false`, и паритет полный. Если владелец против любого расхождения с текстом — только А, и голос людям не включаем до него.
