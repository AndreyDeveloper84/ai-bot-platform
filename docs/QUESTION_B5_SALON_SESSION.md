# Вопрос B-5: как салонная поверхность получает доступ к Ayla

**Дата:** 2026-08-19 · **Статус:** требует решения владельца
**Блокирует:** окно салонной админки, остаток фазы 2 (создание записи, перенос, отмена, завершение визита)

Всё измерено чтением кода `beautygo_backend@origin/dev` и запросами к пилотной БД. Класс — **VERIFIED**, если не помечено иначе.

---

## 1. Что произошло

Салонная админка построена: экран ручной записи, ручка слотов, черновик с правилами, обзор перед созданием. **Создание записи выключено намеренно** — упирается в этот вопрос.

Мутации салона делаются ручками `/api/v1/tenants/me/…`:

```
POST   /api/v1/tenants/me/appointments/                      создание
POST   /api/v1/tenants/me/appointments/<uuid>/reschedule/    перенос
POST   /api/v1/tenants/me/appointments/<uuid>/cancel/        отмена
GET    /api/v1/tenants/me/customers/?q=…                     поиск клиента
```

---

## 2. Чего они требуют

`tenants/appointments_api.py:95-99`:

```python
_SALON_WRITE_PERMISSIONS = [
    permissions.IsAuthenticated,
    IsProApp,
    IsTenantAdmin,
]
```

| Требование | Чем удовлетворяется | Может ли бот |
|---|---|---|
| `IsProApp` | заголовок `X-App-Type: pro` (`users/middleware.py:108`) | **да**, тривиально |
| `IsTenantAdmin` | активная строка `TenantUserRelationship(role=admin)` для **этого пользователя в этом тенанте** плюс заголовок `X-Tenant` (`users/permissions.py:307-327`) | зависит от того, кем он представится |
| `IsAuthenticated` | настоящая пользовательская сессия Ayla | **нет** |

**Бот аутентифицируется служебным bearer'ом** (`AYLA_INTERNAL_API_TOKEN`, схема `IsInternalBearer`). Это не `IsAuthenticated` с пользователем. По этим ручкам он не пройдёт никак.

## 3. Что на пилоте сейчас

```
users_tenantuserrelationship:  admin  — 1 строка
                               customer — 17 строк
```

Единственная админская строка принадлежит `admin@beautygo.ru` — **служебной учётке платформы**, не владельцу салона и не сотруднику.

То есть даже если бы бот умел ходить пользовательской сессией, сегодня ему некем представиться: у людей салона админских прав в Ayla нет.

---

## 4. Три пути

### Путь А — ходить учёткой владельца

Бот хранит долгоживущий токен человека и подписывает им все салонные действия.

**Против:** журнал скажет «владелец отменил запись» независимо от того, кто нажал кнопку в MAX. Мы два дня строили атрибуцию действий — источник закрытия визита, `completed_by`, `no_show_marked_by`, аудит по актору — и этот путь её обесценивает целиком. Плюс хранение чужих учётных данных и их протухание.

**Рекомендую отвергнуть.**

### Путь Б — служебный доступ с указанием, за кого действуем

Ayla принимает на этих ручках `X-Service-Token` + `X-External-User-ID`, резолвит сотрудника и проверяет **его** права.

**Прецедент в проекте уже есть и работает** — `nutrition/views.py:206-218`, `InternalFoodScanView`: «authenticates via shared service token (`X-Service-Token`) and resolves the actor from `X-External-User-ID`». Там же ленивое создание `ProxyUser` при первом обращении.

**За:** переиспользует уже построенный мост личности; атрибуция сохраняется пофамильно; механизм в проекте обкатан.

**Против:** правка в бэкенде Ayla, то есть боевая выкладка. И нужно решить, откуда у сотрудника берётся `role=admin` — вероятно, из погашения кода приглашения, которое уже работает.

**Рекомендую.**

### Путь В — выдавать сотруднику короткоживущую сессию Ayla

При погашении кода сотрудник получает собственный токен Ayla.

**За:** честнее всех по модели — сотрудник и правда становится пользователем Ayla.

**Против:** отдельная система: выпуск, продление, отзыв, хранение на стороне бота, поведение при увольнении. Для MVP дорого.

---

## 5. Что решить

1. **Какой путь.** Моя рекомендация — **Б**.
2. **GO на выкладку бэкенда**, если Б: merge в `dev` бэкенда = боевая выкладка.
3. **Откуда у сотрудника админская роль в Ayla.** Погашение кода приглашения в боте уже создаёт `TenantStaff` на стороне бота — должно ли оно заодно создавать `TenantUserRelationship(role=admin)` на стороне Ayla? Если да, это вторая половина той же правки.
