# RC-1 — что входит, что не входит. Заморозка 26.08 вечером

Составлено 25.08 главным окном. Основание — определение блокера из плана владельца и замеры на живом пилоте.

**Линза, по которой отобрано:** план говорит запускать сначала **одного** человека. Значит RC-1 обязан выдержать ровно одну цепочку:

```
человек пришёл -> Ayla поняла -> записала -> салон узнал -> визит состоялся -> визит закрылся
```

Всё, что не участвует в этой цепочке, в RC-1 не обязано.

## Входит, но упирается в владельца

**Графики четырёх мастеров (DRF-1050).** Это **данные, а не разработка**: письмо салону и час на проставку. Пока их нет, бот предлагает нерабочие слоты каждый день, а новый сеточный гейт проверяет фикцию.

**Поверхность воды.** Запись доделывается, но дашборд в проде закрыт целиком, и за тем же гейтом сидят заглушки активности и рекомендаций. Гейт по секциям, снять целиком, или оставить закрытым — решение владельца.

**`completed_by=system` — authoritative?** Автозакрытие **уже начислило комиссию и отправило запрос отзыва** 24.08 в 16:37. Вопрос не гипотетический.

**#1307** — гвард на утверждение без стражи. Смержить не могу: токену не хватает scope на `ci.yml`.

## НЕ входит в RC-1 — в известные проблемы

Не потому что неважно, а потому что не помещается в один день и не рвёт цепочку одного человека.

| | почему не входит |
|---|---|
| **DRF-1061** — салонный бот, 20 SP | отдельная поверхность, для одного человека не нужна |
| **DRF-1063** — журнал дня салона, 8 SP | салон узнаёт о брони другим путём (анонс в MAX, #1294) |
| **DRF-1066** — нет экрана успеха, **двойная запись** | **спорно, см. ниже** |
| **DRF-968** — тупик discovery → booking | спорно, см. ниже |
| **DRF-1313** — синк тянет мастеров без фильтра | три салона из пяти; для одного пилотного тенанта не рвёт |
| **DRF-1080/1096** — приглашение мастера | провижининг ручной, мастера заводим сами |
| **DRF-1346** — салонный контракт не зовётся | не в цепочке одного человека |
| **DRF-1366/1368/1370** — стирание и экспорт | правовой контур, не цепочка визита |

### Два спорных, которые я бы всё же взял

**DRF-1066 — двойная запись.** Живой случай был: экран успеха не появился, человек нажал ещё раз, создались две брони. Это **прямое попадание в определение блокера** — «двойная запись» названа там дословно.

**DRF-968 — тупик discovery.** Тоже названо в плане дословно: «тупик основного сценария».

**Оба про первого же человека.** Если что-то и двигать внутрь заморозки — то их.

## Корзина, которой в исходном плане нет

**Безопасность релиза.** План считает релиз-механику данностью; у нас она подводила трижды за две недели.

```
DRF-1363   выкладка бэкенда убила базу пилота на полтора часа
DRF-1364   dev бэкенда красный
DRF-1350   автовыкладка бота не срабатывала с 8 августа
DRF-1351   выкладка одной задачи уберёт починку другой
DRF-1406   фикстура PII-подметания протухла — подметание идёт по пустоте
DRF-1411   гвард на отрицательное утверждение без стражи
```

**DRF-1406 и DRF-1411 — предусловия Pilot Readiness, а не техдолг.** Пока фикстура протухшая, мы **не знаем, течёт ли `schedule`**, и не можем честно сказать `P0 = 0`.

**DRF-1351 обязателен до выкладки:** выкладка одной задачи уберёт починку другой. Это ловушка, которая сработает молча.

## Критерий готовности вместо «P0 = 0»

```
для каждого класса блокера существует проверка,
которую ВИДЕЛИ падающей на непочиненном коде
```

Основание — за 25.08 найдено пять причин ложного красного CI, две таймбомбы, PII-подметание по пустому ответу и 64 отключённых теста. **«P0 = 0» на такой оснастке означает «мы ничего не нашли».**
