## (архив) №3 (2026-08-09): РЕШЕНИЕ ВЛАДЕЛЬЦА по §8 — неоднозначности закрыты, но GO пока НЕ дан: раскладку дополняем

### Ответы на неоднозначности (дословно по смыслу, от владельца)

1. **Неоднозначность A (лимфодренаж): ОБЕ позиции** — и 60 минут, и «экспресс 30 минут». Одна компетенция, различается только длительность/формат.
2. **Неоднозначность B: «Классический массаж задней поверхности тела» — ДА, включать** в компетенцию «классический массаж» у Дениса/Инны/Татьяны (они все в этой группе).
3. **Неоднозначность C (Ольга/лазер): ВСЯ категория «Лазерная эпиляция» (14 услуг) + 3 комбо-пакета, ЕСЛИ комбо состоят именно из лазерных зон** — проверь состав комбо по данным (названия/raw_payload) и включай те, что чисто лазерные. Ольга отвечает за лазерную эпиляцию, ограничивать её двумя зонами неправильно.

### GO НЕ дан: следствие «~49 услуг без мастера» — НЕ ожидаемое состояние

Владелец: исходная раскладка описывает только ядро и НЕ является полной staff/service-матрицей. **Принцип «нет в текущей раскладке → убрать мастера» для остальных услуг НЕ применять.** Мутацию не запускать, пока матрица не дополнена.

**Организационная модель владельца (используй как правила построения полной матрицы):**
- ручные массажные услуги → распределить между массажистами (Денис/Инна/Татьяна) согласно их компетенциям;
- аппаратные процедуры → за аппаратными мастерами;
- лазерная эпиляция → за Ольгой;
- услуги лица/уходы НЕ отключать автоматически — сначала определить фактических исполнителей.

**Итоговый инвариант (критерий приёмки матрицы):** каждая реально продаваемая и доступная для записи услуга имеет ≥1 действующего мастера. Исключение — только услуги, сознательно выведенные из продажи (таких пока не названо).

### Твой следующий шаг: ПРОЕКТ полной матрицы (без мутаций)

1. Построй проект полной матрицы «мастер → услуги» для всех 58 услуг по правилам выше. Для каждой строки — пометка уверенности: CONFIRMED (из раскладки/ответов выше) / INFERRED (выведено из модели: например, аппаратка → Ольга, если она единственный аппаратный мастер) / UNKNOWN (исполнителя из модели не вывести — прежде всего «Уходы для лица», «Массаж лица» и подобное).
2. Выложи проект отдельным файлом `docs/formula-tela-full-matrix-DRAFT.md` (таблица: услуга, категория из интейка, мастера, confidence, комментарий) + секцию в REPORT с итогами: сколько CONFIRMED/INFERRED/UNKNOWN, проверка инварианта (какие услуги остаются без мастера).
3. UNKNOWN-строки — это единственное, что пойдёт владельцу на подтверждение; INFERRED он подтвердит/поправит скопом. Финальный GO на мутацию придёт сюда после его подтверждения матрицы.
