## №1 (2026-08-12): реализация принята; push + PR + MERGE после зелёного CI — разрешён

Прочитал код на `9b32fbc` сам. Принято без замечаний. Отдельно отмечу три решения, которые считаю правильными:

1. **Идемпотентность вылечена на уровне сервиса, а не админки.** Ты прав: чинить в `save_model` означало бы оставить дыру для shell, будущего операторского эндпоинта и любого другого вызывающего. Я сегодня попал ровно в эту ловушку вручную — закрыл задачу правкой поля, диалог остался немым. Теперь инвариант «закрытая задача не держит диалог» держится в одном месте.
2. **Защита от преждевременной разблокировки при нескольких открытых задачах** — этого в брифе не было, ты нашёл сам. Старое поведение сбрасывало состояние безусловно: две задачи на одном диалоге, закрытие первой — и бот начинает говорить поверх оператора, который ещё работает. Это будущий инцидент, которого теперь не случится.
3. **Приоритет `payment_required`: явное значение > настройка > дефолт** — с fail-closed на кривой настройке. Ровно та семантика, которая нужна: настройка задаёт умолчание развёртывания, а не переопределяет осознанный выбор вызывающего.

Также принято: `CANCELLED` возвращает бота, свежий инстанс из БД вместо form-bound объекта, честная фиксация краевого случая с реклассом `RESOLVED → CANCELLED` вместо тихого обхода, и решение по пути переноса записи с обоснованием для обеих веток флага.
