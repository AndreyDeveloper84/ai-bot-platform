### Ошибка, которую я допустил на пилоте, и как убрал

**Первый прогон я обернул в откатываемую транзакцию — так делать нельзя, и вот почему.** `generate_concierge_reply` внутри вызывает `asyncio.run`, и концьерж ходит в ORM **из второго соединения**. Внешняя `atomic()` держит блокировки, второе соединение их ждёт — самоблокировка, ход не завершается никогда.

Я убил ssh, но серверный бэкенд остался: **сессия `idle in transaction` провисела на пилотной базе ~15 минут**, и три моих следующих попытки встали на её блокировках. Ущерб для живых пользователей был возможен: вставка `BotUser` и `Conversation` — это путь любого нового человека.

Убрал: `pg_terminate_backend` по пяти своим pid, проверил `pg_stat_activity` — `idle in transaction` ноль. Транзакции откатились, мусора в базе не осталось.

Повторный ход сделал **без внешней транзакции**, с ограничителями, которые не дают прогону пережить себя:

```python
SET lock_timeout = '5s'
SET idle_in_transaction_session_timeout = '15s'
signal.alarm(150)                      # внутри процесса
timeout -s KILL 170 …                  # внутри контейнера, а не на моей стороне
```

Строки, которые ход записал (пробный `BotUser`, диалог, одно сообщение, одна метрика `AIRequestMetric`, профиль клиента), удалил адресно по `channel_user_id='drf1304-probe'` — осталось ноль. Временные файлы с хоста и из контейнера убрал.

**Вывод для контура, шире моей задачи:** «прогнать в откатываемой транзакции» работает для детерминированных веток и **не работает для ходов через концьержа**. Кто будет проверять ходы модели живьём — используйте ограничители выше, иначе оставите пилоту висящую транзакцию.

### Что происходит теперь

```
«какие салоны у вас есть»
  -> 5 салонов строками (название, город, адрес, что там делают)
  -> 5 чипов с названиями

тап по салону
  -> услуги ЭТОГО салона с ценой и длительностью
  -> чипы с услугами

тап по услуге
  -> мастера, которые её оказывают
  -> «Записаться к …» — существующий шов записи (#1020) со штампом услуги (DRF-962)
```

**Ход модели в цепочке ровно один — первый.** Три тапа отвечают чтением по id: ни модели, ни разбора текста, стоимость хода не растёт.

### Как выполнено ваше ограничение «чип обязан вести к тому, что исполнится»

Не обещанием — тремя механизмами.

**Колбэк ловится по префиксу до консьержа.** `cb:catalog:services:{tenant_id}` и `cb:catalog:masters:{service_id}` — та же форма, что разбирает `parse_callback`, и то же место в лестнице ходов, где уже стоят `cb:visit:*` и `cb:discover:book:*`. Сырой «cb:…» модели не достаётся никогда.

**Чипа нет там, где тап привёл бы в тупик.** У салона без загруженных услуг чипа нет — строка «Услуги пока не загружены» и так это говорит. У услуги, которую не оказывает ни один бронируемый мастер, чипа нет: строка с ценой остаётся, кнопка не рисуется (`ServiceCard.has_bookable_master`).

**Устаревший или битый ref отвечает честной строкой:** «Эта карточка уже неактуальна — каталог с тех пор обновился». Салон мог уйти в неактивные между показом и тапом — это гонка, а не ошибка, и провалиться дальше по лестнице она не имеет права.

### Три места, где эта задача сломала бы контур, если бы я их не тронул

**1. Приветствие глотало бы тап.** `needs_onboarding` пропускал мимо себя `cb:discover:*`, но про новые чипы не знал. У **всех** глобальных `BotUser`, заведённых до флага, `welcomed_at IS NULL` — первый же тап живого пилотного пользователя ушёл бы в приветствие. `cb:catalog:*` добавлен в тот же пропуск, рядом с `cb:discover:*` и по той же причине.

**2. Сырой колбэк оседал бы в истории диалога.** DRF-988 уже находил это на `cb:book:*`: модель читала payload как сказанное человеком и галлюцинировала на нём («отказ про 2026 год»). Тап по чипу — не реплика; пользовательский ход для `cb:catalog:*` больше не пишется. Ответ бота пишется как раньше — это и есть заземление следующего хода.

**3. Список карточек резался на полуслове.** `_MAX_REPLY_CHARS = 600` — поводок для **прозы модели**, он так и записан в промпте. Живые пензенские строки длинные:

```
• Центр коррекции фигуры «Afrodita» — Пенза, ул. Московская, 74, БЦ «Московский»
  Что делают: Лазерная эпиляция подмышечных впадин, …
```

Пять таких салонов в 600 символов не влезали: хвост обрезался, **а чипы для срезанных строк всё равно рисовались** — текст и кнопки расходились. У детерминированного списка теперь свой бюджет, ветка консьержа не режет его повторно.

### Чем доказано

**68 тестов, зелёные на Postgres** (`apps/orchestrator/tests/test_catalog_surface.py`, `apps/marketplace/tests/test_discovery_salons_services.py`, `apps/channels/tests/test_global_catalog_chips.py`), плюс весь `apps/channels` целиком — 471 зелёный.

Локально часть `apps/orchestrator` падает и один тест виснет — это машина без Redis (вы предупреждали в §7, здесь список шире трёх файлов). Верить надо CI: он гоняет те же файлы на моём коммите и зелёный.

Не только рендеры. Тесты гоняют:

* всю цепочку тапов через `handle_global_max_event` — с проверкой **настоящей MAX-клавиатуры в исходящем сообщении**, а не только `action_data`;
* коллизию имён: «Формула» и «Формула тела» — тап по первому отдаёт услуги только первого (ради этого колбэк несёт id, а не имя);

Локально я проверял mypy только по изменённым файлам исходников, тесты в проверку не попали. Исправлено `b980899`, урок записан: перед пушем гонять mypy по дереву, а не по списку.

### Что прошу прогнать после мержа (§8)

```
«какие салоны у вас есть»   -> пять салонов + пять чипов
тап по чипу салона          -> услуги этого салона + чипы услуг
тап по чипу услуги          -> мастер + кнопка записи
```

Третий ход — не формальность, см. вопрос 1 ниже.

### Что я поправил в вашем брифе

**«Кнопками это не чинится»** (§5) — верно про приветственную клавиатуру и неверно про эту задачу; ваш Ответ 1 это уже признал. Подтверждаю замером: `_build_attachments` собирает MAX-клавиатуру из `action_data` без единой правки инфраструктуры, тест проводит её до исходящего сообщения.

**«Инструменты консьержа предел пяти кнопок не тратят»** (§5) — теперь тратят: пять чипов салонов и до восьми чипов услуг. Конфликта нет (пять кнопок DRF-1200 живут на тенантном пути, пилотный пользователь их не видит), но утверждение больше не верно — знайте.

**Салонов показываю пять, не восемь.** «Какие салоны у вас есть» просит ответ, а не каталог; остальное уносит хвост «…и это не все — назовите город, покажу точнее». Тот же предел, что у карточек мастеров.

### Границу DRF-1295 не трогал

Печатается только то, что лежит в зеркале. `price_from` NULL или 0.00 не превращается в «от 0 ₽», пустой адрес — не в «None», непривязанная к канону услуга показывается как есть. Выдуманных салонов, цен и длительностей нет ни в одной ветке.
