### 3.4 Три блокера, ни один не в диффе `699639c`

**A — каталожный миррор налил декартово произведение master × service.**

Следствие: список мастеров одинаков на любой запрос, фильтрации по услуге фактически нет; бот предлагает мастеру услуги, которых тот не оказывает (массажный запрос → «Must Have (подмышки+ глубокое бикини)»). → **DRF-969**

Это задекларированное поведение фикса (авто-выбор одной из нескольких молча записал бы клиента не на то), но **альтернативы выбору нет** — нужен in-skill service-picker кнопками, как в решении по need-first booking (Fork1 #1016, Option 2). → **DRF-970**

**C — залипший интент + ask-the-service не потребляется.**
Точное «RF-лифтинг — Лицо/шея/декольте» по данным даёт **однозначное** совпадение, но живая карточка услугу не получила → в tool-вызов ушла не эта строка. Тот же залипший ранний интент виден на «Кавитацию» («могу помочь с записью на классический массаж»). Плюс ответ на вопрос об услуге уходит в новый discovery-turn вместо продолжения записи. Отдельно: `orchestrator.concierge.show_masters` логирует только `count`, без аргументов — причину пришлось выводить косвенно, это дыра в наблюдаемости. → **DRF-971**

## 5. Механика хоста — что выяснилось попутно (пригодится следующему окну)

1. **Хост не имеет доступа к GitHub.** `origin` (https) → `could not read Username`; `ssh-origin` → `Permission denied (publickey)`. Единственный рабочий путь доставки кода — `git bundle` + `scp`. Ref внутри бандла называется `refs/remotes/origin/dev`, а не `dev`:
   ```
   локально: git bundle create x.bundle <host-SHA>..origin/dev
   scp x.bundle taximeter@194.87.99.126:/tmp/
   на хосте: git fetch /tmp/x.bundle refs/remotes/origin/dev:refs/tmp/<slug> && git checkout <SHA>
   ```
2. **Репо на хосте живёт в detached HEAD**, `git branch --show-current` пустой — это норма.
3. **Compose — ровно три файла** (третий, `docker-compose.staging.local.yml`, untracked и существует только на хосте). Запуск без него даст не тот стек.
4. **Health-путь `/healthz/`**, не `/health/`.
5. В `git status` на хосте постоянно висит пачка `??` (бэкапы `.env.staging.*`, `.chromadb/`, `data/`) — критерий чистоты не «пусто», а «нет tracked-изменений».
6. Диск: 79G, 81% занято; `docker system df` показывал ~20GB reclaimable build cache — резерв на случай, если сборка упрётся.
7. `MasterService` на задеплоенной схеме **не имеет** поля `is_active` (есть `ayla_specialist_service_id`, `master`, `service`, `tenant`) — при написании диагностических запросов это ловушка.
