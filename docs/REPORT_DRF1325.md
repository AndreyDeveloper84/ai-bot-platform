# Пять опровержений постановки

**Три из пяти меняют то, что надо было строить.**

## 1.1. Резолвер намерения использовать нельзя — по конструкции, не по состоянию

Бриф главного окна: «Проверь первым делом, что резолвер даёт после починки. Возможно, разбор времени там уже есть».

`apps/orchestrator/intent_resolution.py`, собственный докстринг:

> **After the reply, never before it.** The resolver runs once the answer is already sent […] a resolver failure can never change what the user saw.

Контракт 0.5 рождается **после** отправки ответа и пишется **только в журнал хода**. Сузить выбор «до того, как показан календарь» он не может **ни сейчас, ни после #1245**. Чтобы им пользоваться, пришлось бы поставить лишний вызов модели перед каждым ходом записи — ровно то связывание задержки и отказа, ради отсутствия которого модуль так и написан.

Плюс: его слот `time_preference` — конверт со свободным текстом от модели, **без границ суток и без пояса**. Даже получив его, «вечер» пришлось бы определять заново — то есть делать ровно эту задачу.

**Сделано вместо:** детерминированный разбор без модели. Ноль вызовов LLM, ноль новой задержки, ноль зависимости от судьбы #1245.

## 1.2. Часовой пояс мастера этому сервису недоступен

Он живёт в бэкенде Ayla. В зеркале бота его нет: у `CatalogMaster` **нет колонки `timezone`**, фид специалистов её не приносит.

Честный локальный источник — **`Tenant.timezone`** (default `Europe/Moscow`), он уже используется для «завтра в 10:00» в напоминаниях.

И это **не компромисс**, а именно то, что предписывает `docs/REPORT_SALON_P0.md»: там речь про бэкенд Ayla, где пояса у арендатора нет. В боте он есть, и одна локальная дата на салон — это и есть уход от ловушки: **девять мастеров получают один «завтрашний вечер», а не девять разных**.

## 1.3. Трасса в задаче сокращена — бот не выбирал 28.08 сам

За 11 секунд между списком услуг и «Записываю: 28.08 11:30» было **два тапа владельца** — по дате и по времени. `28.08` — первый день, где 14-дневный веер нашёл хоть что-то; `11:30` — первый слот дня.

**Почему важно:** дефект целиком в том, **что предложено**, а не в самовольном выборе. Значит чинится в отрисовке, **без прикосновения к `create`**. Если бы бот действительно выбирал сам, задача была бы другой и куда опаснее.

## 1.4. «Не строить поиск свободного времени» — расписание уже читается, иначе чипы врали бы

Поток **уже** делает до 14 однодневных чтений (`get_available_dates`). **Новых видов запросов не добавлено** — чипы строятся из того же чтения.

И именно **из него**, а не постоянным рядом: требование «чип обязан вести к тому, что исполнится» несовместимо с жёстким `[Сегодня][Завтра][Послезавтра]` — у мастера может не быть завтра, и кнопка ведёт в тупик.

Чип дня появляется, **только если день вернуло чтение**; чип «Вечер» — только если в дне есть слот после 17:00.

**Ни одна строка не утверждает, что время гарантированно свободно** — `docs/OD_SALON_P0_CONTRACT.md` соблюдён дословно, последнее слово за `create` и 409.

## 1.5. Признание запроса нельзя приписать к ответу консьержа

Хранилище консьержа пишет ход в `Message` **до** возврата в обработчик (`persisted=True`). Приписав строку после, исполнитель **отправил бы одно, а записал другое** — а из записи читают фикстуры воспроизведения.

Поэтому признание добавлено только там, где ответ ещё не записан (детерминированная ветка `show_masters` — путь пилота), а на пути консьержа запрос проговаривается на шаг позже, самим пикером. **Предпочтение сохраняется всегда, на обоих путях.**

# Что построено

## Одно место для границ суток

`apps/orchestrator/time_preference.py`:

```
Утро   — до 12:00
День   — 12:00 … 17:00
Вечер  — с 17:00
```

`part_for_hour()` **тотальна на 0..23**: три ведра покрывают сутки без зазора, слот не может выпасть из словаря и молча получить не ту подпись — **это и есть защита от «вечера в 14:30»**.

Границы едут вместе со словом: чип подписан «Вечер (с 17:00)», смысл виден **до** нажатия.

Пятизначный словарь персонального контекста (`early_morning…late_evening`) сведён к этим трём в той же таблице.

## Вход

«завтра вечером», «послезавтра утром», «в субботу», «в выходные», «после работы», «после шести», «после 18». Числовые формы прогоняются **через ту же `part_for_hour`**.

Дни недели разбираются только когда передан сегодняшний день недели — **без него ветка пропускается, а не угадывается** по дате сервера.

Хранится 10 минут в `Conversation.skill_state`; просроченное не применяется.

## Выход

```
[Сегодня]  [Завтра]  [Послезавтра]  [Выбрать дату]
[Утро (до 12:00)]  [День (12:00–17:00)]  [Вечер (с 17:00)]  [Точное время]
```

Чип дня — **существующая** кнопка `cb:book:pick_date:` в человеческой одежде: грамматику не менял, её маршрутизируют три слоя. Новых префикса два.

Три сокращения убирают лишний тап: названная часть суток → сразу слоты; одна непустая часть → сразу слоты; «Точное время» всегда рядом. **Когда времени нет — это произносится вслух, а не проглатывается.**

Приветствие не тронуто — предел пяти кнопок DRF-1200 в силе.

# Собственный баг, найденный и починенный

**Важно для доверия к остальному.**

Первая версия переноса предпочтения через границу арендатора читала исходный разговор через `resolve_active_conversation`. Тот ищет **внутри** `tenant_scope`, в который вызывающий только что вошёл, — а глобальный разговор припаркован под сентинелом `global_bot` **снаружи** этого скоупа.

Функция компилировалась, проходила mypy и возвращала `None` **на каждом ходе**: вся работа тихо деградировала на путь «время не названо».

**Ни один тест этого не видел** — все били по разбору и по отрисовке, а не по шву.

Починено (`resolve_active_global_conversation`, `create_if_missing=False`) и закрыто **отдельным тестом на сам шов**, который на прежнем коде падает.

# Сценарий живого прогона

Никаких откатываемых транзакций — §0-ter соблюдён.

## A — главное доказательство

1. `хочу на массаж завтра вечером` → первой строкой **«Поняла: завтра вечером. Подберу время под это.»**, ниже мастера.
2. тап по мастеру:
   - есть завтрашний вечер → **«Вы просили завтра вечером — вот что есть:»**, кнопки только **с 17:00** и только **завтрашние**;
   - вечера нет, день есть → «Завтра вечером у мастера свободного времени нет. Есть так:» + чипы реальных частей суток;
   - завтра не работает → «На завтра у мастера свободного времени нет. Вот ближайшие дни:» + чипы дней.
3. тап по времени → превью → подтверждение.

**Провал A:** после шага 1 про время ни слова, либо на шаге 2 есть время до 17:00 или не завтрашняя дата.

**Если вместо завтрашнего вечера показались чипы дней — смотреть шов из раздела выше первым делом.**

## B — чипы

1. `запиши на массаж` → мастера, про время ничего.
2. тап по мастеру → «Выберите дату:» + `[Сегодня][Завтра][Послезавтра][Выбрать дату]`.
3. тап `Завтра` → «Когда удобно завтра?» + чипы только тех частей, где есть слоты.
4. тап `Вечер (с 17:00)` → только времена с 17:00.
5. вместо шага 4 тап `Точное время` → весь день, прежнее поведение цело.

**Отдельно:** пройти по каждому чипу — ни один не должен вести в пустоту.

# Найдено рядом, не чинил

`get_available_dates` берёт 14-дневное окно от даты **сервера** (UTC). Москва на три часа впереди — с 00:00 до 03:00 по салону окно открывается на вчерашнем дне и на день раньше закрывается.

Общий клиент, арендатора не знает — вне рамок. Смягчено: «сегодня» считается в поясе салона, а относительное слово не ставится на прошедший день (закреплено тестом).
