# Состояние поверхности бота

**Ещё не снято ни разу.** Этот файл — заглушка из PR DRF-1661: он существует,
чтобы у команды было куда писать, а у читателя — понятное место, где искать.
Числа появятся после первого прогона на пилоте:

```
docker compose -p ayla-bot-staging exec -T web python manage.py surface_state --write docs/SURFACE_STATE.md
```

Шаг выкладки (`deploy-dev.yml`) перепишет файл в дереве выкладки после
`up -d` и smoke — **не коммитить**: это вывод, а не источник. В репозитории
остаётся заглушка.

Что окажется здесь после прогона (в этом порядке):

1. **Предмет** — кто отвечал на замер: hostname процесса, id контейнера,
   адрес БД по настройкам и по её собственному ответу, время старта
   процесса БД, пульс по нескольким опорам с возрастом каждой, время снятия.
   Молчание всех опор печатается как «свежесть НЕ подтверждена», не как ноль.
2. **Предел** — данные и значения рубильников, а не поведение.
3. **Рубильники** — живое значение каждого флага из `settings` и задан ли он в
   окружении (§138: построено, но `false` — ЗАПЕРТО). `GOAL_RESOLUTION_ENABLED`
   печатается как «не setting бота»: он живёт в каталоге.
4. **Числа** — тенанты бота, пользователи, карточки мастеров
   (`linked_bot_user`, `ayla_user_id`, `invite_status`), `setup_state`
   соло-мастеров тем же `sale_block`, что у витрины; у каждого числа рядом
   таблица и поле, из которых оно снято.

Парная команда каталога: `beautygo_backend` `manage.py surface_state`
(PR #337) — та же шапка, свои числа.
