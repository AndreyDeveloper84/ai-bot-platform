## Правила

**Запуск** — действие владельца. Главное окно готовит бриф и **разводит каталоги**.

**Процесс** — файловая шина: `REPORT_<имя>.md` от окна, `REPLY_<имя>.md` от главного окна. Мутации Linear — только главное окно.

**Перед merge — сверять коммит.** `gh pr view <n> --json headRefOid` против `HEAD` ветки. Введено после DRF-1155.

**После merge — сверять содержимое.** Squash-merge закрывает PR на одном коммите; всё, что окно дописало позже, остаётся на ветке невидимым. 19.08 так повисли две готовые работы.

**Дефект — сразу в Linear, в тот же ход.** Обещание в чате не является записью в Linear.

**Фронт собирается отдельно.** Порядок выкладки не трогает Mini App — это статика, собираемая своей командой под Node 20. 20.08 выяснилось, что сборка отставала на двенадцать дней.

**GO — что требует разрешения владельца:**

| Действие | GO |
|---|---|
| коммит и пуш в свою ветку | **не нужен**, и требовать его вредно |
| открытие PR, merge бота при зелёном | не нужен, делает главное окно |
| **merge бэкенда** | **нужен** — немедленная боевая выкладка |
| **мутации на пилоте** | **нужен** |
| **гашение живого инцидента** | **не нужен** — действовать сразу, но сказать в отчёте немедленно |

## История: что дал этот способ работы

**Норма опровержения брифа.** Окна и сабагенты опровергли постановку главного окна **семнадцать раз** за шесть дней, и каждый раз были правы. Все — замером или чтением первоисточника, ни одно — рассуждением.

Из них **семь — ошибки главного окна**, и они записаны здесь намеренно: реестр, показывающий только чужие промахи, для сверки бесполезен.

Три последние пришли одной пачкой 20.08 — сабагент, которому поручили сверку канона с кодом, попутно опроверг три моих утверждения о самом каноне. Брифу это стоило дешевле, чем стоила бы работа по завышенному приоритету.

| Что опровергнуто | Чем |
|---|---|
| «воронка требует город» | замером: город назывался, петля продолжалась |
| «бот предлагает несуществующие услуги» | чтением каталога: две из трёх реальны |
| «UX-контракт запрещает новую сущность» | чтением первоисточника |
| «корень зацикливания — промпт» | аудитом легаси |
| «красный PR — это конфигурация CI» | логом: чужой тест откатывал миграции |
| «у мастерского пути своя проверка» | чтением: проверка общая |
| «коды админских экранов есть в логах» | замером: за 14 суток обращений **ноль** |
| «превью показывает 0 при 23 бронях» | счётом: будущих подтверждённых **одна** |
| «внутренний чат — чинить в `internal_chat`» | контрольным запросом: отвечает middleware |
| **«клиентский бот упал на 9 секунд»** | отчётом окна: 44 перезапуска, сорок минут |
| **«`_collect_occupied` — живой дефект»** | историей: закрыт гейтом за день до |
| **«кодировка канона восстановлена»** | round-trip детектором: две строки другого семейства |

| **«кодировка канона восстановлена» (второй раз)** | round-trip детектором: ещё 25 строк третьего семейства |
| **«решения BOT-001 существуют вне git и могут быть утеряны»** | чтением спецификации: канонизированы в §22–23 под git. Утеряны номера, не содержание — DRF-1195 понижена |

| **«аудит канона указывает на нужный файл»** | исполнителем: файла по указанному пути нет вовсе, строки указывают в докстринг |
| **«нарушение #22 локализовано одним местом»** | исполнителем: третья точка входа зовёт ту же функцию **в обход LLM**, в аудите её нет |
| **«вебхук салонному боту подписан, оба бота работают»** | замером 20.08: подписка салонного **выбила клиентского**, тот сутки жил на мёртвом туннеле |
| **«требование зафиксировано красным тестом»** | `git diff`: теста в коммитах нет, а существующий утверждает **восемь** кнопок вместо девяти |

**Ещё два инструмента, совравшие в один вечер** — оба мои, оба в одном разборе:

- `sudo grep` по логам nginx показал «ноль обращений за неделю»; `sudo` требовал пароль, и весь замер был пустым;
- запрос подписок MAX с токеном в параметре показал «0 подписок у обоих ботов»; MAX этот способ больше не принимает, а разбор прочитал пустой список **из тела ошибки**. Я чуть не доложил полный отказ обоих ботов.

Общее у обоих: **отрицательный результат выглядит так же, как сломанный инструмент.** Проверять инструмент обязательно тогда, когда он показывает ноль.

**Пять проверок, которые выглядели убедительно и измеряли не то** — отдельный список, потому что это самый дорогой класс ошибок:

- `curl` отдавал 200 на любой путь одностраничного приложения;
- `docker exec grep` видел новый файл, пока процесс работал на старом коде;
- `git merge-base` при squash-merge всегда говорит «не влито»;
- `grep` по списку категорий сломался на переносах строк Windows — «отсутствуют все 12 из 12»;
- монитор TLS проверял корень API, у которого корня нет.

**Разделение труда:**

- **окна** пишут код, гоняют тесты, ведут ветку, отвечают за регресс;
- **сабагенты** меряют и описывают — не переживают обрыв, но закрывают диагностику дёшево;
- **главное окно** сводит, заводит в Linear, мержит, выкладывает и **меряет живое** — доступ к пилоту и обеим базам есть только у него.
