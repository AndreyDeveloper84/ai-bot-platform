# DRF-2532 — аллергия и постоянная память: замер

**Деревья:**
- бот — `ai-bot-platform` `origin/dev` `0a0dd57f`;
- каталог — `beautygo_backend` `origin/dev` `d0aa7c98`, читался через `git grep/show`;
- ai-core — `ayla-ai-core` `origin/main` `d72a5de`.

**Предмет:** предусловие DRF-1290 «аллергии — отдельный периметр, не зелёная память». Поведение не менялось ни в одну сторону, видимого текста не добавлено.

**Способ:** перепись писателей и читателей — по конструктору и вызову (`MemoryEntry.objects.*`, `.save`, `.update`, CASCADE, сериализаторы, admin, команды, задачи, сигналы, HTTP), а не по именам полей. Каждое утверждение ниже сверено с файлом. Экстрактор проверен живым прогоном на восьми формулировках.

## Коротко

1. **Сегодня «у меня аллергия на орехи» в постоянную память бота не попадает.** Фрагмент со словом «аллерг» или «непереносимост» отбрасывается до записи, в журнал пишется причина `allergy` без текста.
2. **Та же аллергия, сказанная другими словами, тоже не попадает, но уже без следа.** Примеры: «мне нельзя орехи, задыхаюсь», «не переношу лактозу». Экстрактор её не распознаёт как аллергию; её просто нет в его закрытом словаре. `drops=[]`, в журнале ничего.
3. **Зоны есть в одном контуре из двух.** В боте зоны green/yellow/red и CHECK есть. В каталоге зон нет, а там лежат `skin_sensitivities` («аллергены / чувствительность») и `health_flags.allergies`. Оба зелёные по построению, и первое уходит в промпт AI-чата каталога.
4. **Жёлтая зона сегодня недостижима.** Любая запись yellow/red молча отбрасывается на заглушке защиты несовершеннолетних, ещё до INSERT и до CHECK.
5. **Читателей, которые обращаются с зонами по-разному, — 2 из 14, а у жёлтой зоны своего обработчика нет ни одного.**

## 2. Что уже лежит

SQL: `docs/measurements/DRF-2532_allergy_memory_counts.sql`. Только чтение (`READ ONLY` + `ROLLBACK`), только количества.

**Признак отбора — `kind IN ('contraindication','symptom')`, а не текст.** Причина: `content` зашифрован Fernet'ом, и подстроки в базе нет.

**Пределы:** каждое число рядом с ними — нижняя граница.
- Медицинский факт, записанный как `preference`/`other`, в счёт не попадёт.
- **Красная зона этим SQL не меряется по построению.** RLS-политика `memory_entry_non_red_visible` (0008, RESTRICTIVE, FORCE) прячет red без GUC и возвращает ноль, а не ошибку. `ayla_ops` видит только `memory_entry_safe`, где red исключены.
- Блока с GUC в SQL нет намеренно: это обход защитного слоя, и решение о нём не моё.

**Ожидание по коду:** живых yellow/red-строк нет. Писатели пишут только green, а `write_entry` отбрасывает yellow/red на заглушке (раздел 3). Запрос 3 SQL это проверяет, запрос 4 показывает `convalidated` констрейнта.

## 3. Что требует констрейнт

**По коду констрейнт объявлен так** (конец цепочки: 32 миграции `apps/identity`, имя упоминает только `0007_user_personal_context.py:87`, ни одна последующая его не снимает и не заменяет):

```sql
CHECK (
  sensitivity_zone = 'green'
  OR (sensitivity_zone IN ('yellow','red')
      AND (consent_at IS NOT NULL OR soft_deleted_at IS NOT NULL))
) NOT VALID;  -- затем VALIDATE CONSTRAINT
```

- **Зоны:** green, yellow, red. Для green не требуется ничего.
- **Согласие:** `consent_at IS NOT NULL` на строке. Надгробие (`soft_deleted_at`) тоже удовлетворяет условию. Это отметка времени на самой записи, а не ссылка на запись согласия.
- **Второй прибор, `Meta.constraints`:** констрейнта там нет, **намеренно** (комментарий `models.py:1174–1185`: RunSQL ради разделения NOT VALID/VALIDATE). Два прибора не сходятся по замыслу. Попутно: докстринг модели ссылается на «migration 0005», а на деле это 0007.
- **Только Postgres:** на SQLite миграция — пустая операция.
- **«На стенде validated»** — эту строку подтверждает или снимает главное окно (запрос 4 SQL). Здесь она не утверждается.

**Что происходит при записи yellow без согласия — три исхода различаются:**

| Состояние | Исход |
|---|---|
| **сегодня** | **тихий пропуск до базы.** `write_entry` для yellow/red сначала зовёт `_check_minor_protection` (`memory_writer.py:66`). Это заглушка Phase 0: она всегда бросает, потому что ручки даты рождения нет (#597). Итог — `return None` и строка аудита `write_rejected_dob_lookup`. Отбрасываются **100% записей yellow/red, с согласием или без**; CHECK недостижим. |
| после снятия заглушки | **отказ базы** (`IntegrityError` от CHECK). В коде приложения проверки согласия до CHECK нет (`memory_writer.py:157`: «CHECK 2 enforces it»). |
| как этот отказ увидит человек | **снова тихий пропуск.** Адресно `IntegrityError` не ловится, его проглотят общие `except Exception` у вызывающих (`personal_context.py:233`, `food.py:694`). У `said_memory._write_said_fact` своего `try` нет. |

**Удаление:**
- `soft_delete_green_entries`: только green.

## Решения для владельца

1. **Куда кладём аллергию, сказанную человеком?**
   - (а) никуда, как сейчас: отброс с причиной в журнале;
   - (б) в red с явным согласием, через `promote_zone` / `consent_token`;
   - (в) в отдельное хранилище вне памяти (профиль питания/ухода) со своим согласием.

   От ответа зависят 2–6.
2. **Как узнавать аллергию, сказанную без слова «аллергия»?** («мне нельзя орехи, задыхаюсь», «не переношу лактозу» сегодня проходят без следа.)
   - (а) оставить подстроку и назвать предел;
   - (б) расширить словарь признаков (быстро, но всегда неполно);
   - (в) классификатор здоровья, который уже есть в скрининге S1, — с ценой вызова на каждую реплику.
3. **`skin_sensitivities` и `health_flags.allergies` в каталоге сейчас зелёные, и первое уходит в промпт AI-чата каталога. Что с ними делать?**
   - (а) оставить: человек вписал сам в форму, это согласие;
   - (б) перевести в отдельный периметр со своим согласием и журналом;
   - (в) убрать из промпта, оставив хранение.
4. **Должен ли forget-all стирать `skin_sensitivities` в каталоге?** Сегодня тест закрепляет, что не стирает.
   - (а) да, «забудь всё» значит всё;
   - (б) нет, это данные анкеты, а не память.
5. **Нужна ли жёлтая зона вообще?** Сегодня писателей у неё нет, показа нет, выгрузки нет, поштучного удаления нет, TTL нет.
   - (а) убрать из модели до первого писателя;
   - (б) оставить и достроить четыре читателя до того, как появится писатель.
6. **Выгрузка по 152-ФЗ: включать ли yellow/red?** Этот вопрос уже записан в `export_coverage.py` как вопрос к владельцу.
   - (а) включать, red через `RedZoneReader` с журналом;
   - (б) не включать и сказать человеку в выгрузке, что есть категории, выдаваемые по отдельному запросу.
7. **Снятие заглушки даты рождения (#597) откроет запись yellow/red.** До этого нужны:
   - (а) проверка согласия в `write_entry`;
   - (б) адресная обработка `IntegrityError`;
   - (в) TTL-свип;
   - (г) перезапуск forget-all не только по green;
   - (д) журнал red в `account_reset`.

   Вопрос владельцу: делать ли (а)–(д) условием снятия заглушки?
8. **Можно ли считать красные строки на стенде?** SQL их не видит по построению RLS. Варианты:
   - (а) break-glass по runbook с журналом;
   - (б) счёт через `RedZoneReader` отдельной командой;
   - (в) не считать и принять, что по коду их ноль.

## Пределы замера

- Текст памяти не мерялся: он зашифрован, а расшифровка на стенде запрещена. Счёт по `kind` — нижняя граница.
- Красная зона в SQL не видна (RLS). Её ноль ничего не значит.
- Блокировку `said_memory` в пробе я приблизил проверкой подстроки `_HEALTH_STEMS`, а не вызвал сам код.
- Сырой текст реплик в `Message` (история диалога) — вне предмета. Аллергия там лежит, как и всё сказанное.
- Каталог мерялся по `origin/dev`. Что развёрнуто на стенде, не проверялось.
