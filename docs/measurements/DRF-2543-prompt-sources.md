## Находки

**F1 — `favorite_masters` в подсказке без салона, дважды.** Местный факт — «называешь любимым мастером «<имя>»» (`memory_surface.py:99`, группа сказанного). Каталожный — «Любимые мастера: id=<uuid>» в секции выведенного: бот не передаёт `master_names`, модель видит голые UUID. Агрегация каталога сама пересекает салоны. Решение 2026-08-24 (`personal_fields.py:108`, `POLICY_DEBT`) запрещает переход факта **между салонами**; глобальная Ayla — не салон, и из ответа модели в салон уходит только `start_booking(master, service, city)` (`concierge.py:587`). Живой утечкой к салону не является. Механизм из самого решения (`source_tenant_id` проверяется при чтении) не построен — DRF-2544.

**F2 — провенанс `summary`.** По `POLICY_DEBT` (`personal_fields.py:120`) это вывод по определению, а рендер кладёт его в группу «что ты уже знаешь» рядом со сказанным. Сегодня поле пусто (DRF-2526, #2087).

**F3 — в подсказке, но не в выгрузке.** S5, S6, S8. Все три объявлены исключениями с причиной, не умолчанием.

**F4 — свободная строка не от человека и не из нашего кода.** `hint` питания из Ayla, категория здоровья.

**F5 — мёртвый путь.** `generate_discovery_reply` с `personal_context` — 0 боевых вызовов.

## Передача человеку (handoff) с глобальной поверхности

Два пути к салону; **содержимое подсказки не попадает ни в один.**

**H1 · «нужен человек»** — `handler.py:2065` → `route_global_human_handoff` (`apps/orchestrator/handoff.py:1425`).

* Триггер — подстрока в целом сообщении (`matches_human_handoff_request`, `handoff.py:1337`; ключи `apps/skills/human_handoff/skill.py:34`); отсекается только «не»/«без» перед словом.
* Задача ложится в **последний по времени салонный разговор** человека (`_latest_tenant_conversation`, `handoff.py:1476`), иначе — в очередь платформы.
* `reason` = «Global-path trigger phrase: » + первые 80 символов сообщения. `transcript_snapshot` — разговор этого салона. Салонный диалог переходит в `HUMAN_HANDOFF`.
* Кто видит. Операторы платформы — уведомление с `reason` (`apps/handoff/notify.py:126-154`). Салон — `handoff_waiting_notice` (`apps/channels/max/salon_notify.py:477`): «Клиент <имя> ждёт ответа», **без `reason` и без текста**. Экран очереди салона `reason` и снимок не отдаёт (`apps/admin_api/views_handoff_queue.py:16`). `reason` видна в Django-админке, которая кросс-тенантная и по политике выдаётся только внутренней команде (`apps/handoff/admin.py:144-156`, DRF-1023) — ограничение словами, не правами (DRF-1022).
* Пересечение: сообщение о салоне Б будит салон A, если с A человек говорил последним. Текст к A не уходит; факт обращения и замолкание диалога — уходят. Отдельный лист — **DRF-2545** (выбор адресата эвристикой «последний разговор»).

**H2 · запись в салон по карточке мастера** — `handler.py:3154` → `handoff_to_booking` (`handoff.py:279`). В контекст записи салона едет `query_ref` — закодированный текст запроса человека (DRF-1324, `apps/orchestrator/booking_context.py:78-99`). Читает его код, чтобы сузить меню услуг.
