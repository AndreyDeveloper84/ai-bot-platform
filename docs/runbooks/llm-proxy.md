# Runbook — внешний LLM-прокси: проверить, заменить адрес, убедиться

> DRF-2065. Инцидент 16–17.09.2026: прокси отказал на уровне TCP, прямой путь к
> Anthropic при этом был. Простой 9 ч 15 мин; между правкой `.env.staging`
> (05:55) и пересозданием контейнеров (06:24) бот полчаса ходил по старому адресу.

## Зависимость

| Что | Значение |
|---|---|
| Владелец прокси | _не заполнено — вносит владелец проекта_ |
| Основной адрес | только в `.env.staging` на хосте (`ANTHROPIC_PROXY`, при пустом — `OPENAI_PROXY`) |
| Запасной адрес | _не заполнено — вносит владелец проекта (без учётных данных)_ |
| Нужен ли прокси при живом прямом пути | _решение владельца; срок годности прямого пути из РФ — назвать здесь_ |

Учётные данные прокси сюда не пишутся — никогда.

Правило выбора прокси в коде одно: `AnthropicProvider.configured_proxy()` —
пустой `ANTHROPIC_PROXY` молча уступает `OPENAI_PROXY`. Проверять нужно тот
адрес, который реально в работе, то есть обе переменные.

## Как понять, что лёг именно прокси

1. Алерт «🔴 LLM недоступна» / «🟠 Основной путь к LLM недоступен — работаем на
   резерве» несёт строку **«Прямой путь к провайдеру: есть — сеть жива, менять
   нужно прокси»**. Хост прокси в строке «Детали» виден, учётные данные — нет.
2. `readyz` показывает путь в теле, код ответа от LLM не меняется (200):
   `checks.llm.state` — `primary` (основной жив), `fallback` (работаем на резерве
   DRF-2147), `down` (оба лежат), `unknown` (не мерили или мерили давно).

Проба меряет раз в 5 минут, поэтому `readyz` отстаёт от правды не больше чем на
тик. 503 при «оба лежат» не делаем сознательно: деплой-смоук (`curl -fsS
/readyz/`) упал бы ровно на выкатке починки.

## Замена адреса — три строки

Всё — в каталоге стенда (там, где лежит `.env.staging`), от того же
пользователя, от которого работает `deploy-dev.yml`.

**1. Проверить новый прокси ДО пересоздания.** Любой HTTP-код (401, 405) —
прокси живой; `000` — нет. Адрес держите в переменной оболочки, не в истории:

```bash
curl -sS -o /dev/null --max-time 15 -w '%{http_code} %{time_total}s\n' -x "$NEW_PROXY" https://api.anthropic.com/v1/messages
```

**2. Вписать адрес в `.env.staging` и пересоздать все сервисы, читающие env.**
Env читается при создании контейнера — правка файла сама не применяется. Три
файла compose — ровно те, что у деплоя; без третьего `web` пересоздастся с
неверной конфигурацией, а `celery-worker` не найдётся:

```bash
docker compose --env-file .env.staging -f docker-compose.yml -f docker-compose.staging.yml -f docker-compose.staging.local.yml -p ayla-bot-staging up -d --force-recreate --no-deps web worker shadow-worker celery-worker celery-beat
```

**3. Убедиться, что контейнер видит новый адрес** (печатается только хост):

```bash
docker compose --env-file .env.staging -f docker-compose.yml -f docker-compose.staging.yml -f docker-compose.staging.local.yml -p ayla-bot-staging exec -T web python -c "import os, urllib.parse as u; p = os.environ.get('ANTHROPIC_PROXY') or os.environ.get('OPENAI_PROXY'); print(u.urlsplit(p).hostname if p else '<пусто>')"
```

После — дождаться следующего тика пробы (≤ 5 мин): придёт «🟢 LLM снова
доступна», `checks.llm.state` станет `primary`.
