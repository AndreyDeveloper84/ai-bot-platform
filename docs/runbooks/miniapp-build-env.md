# Runbook: Mini App — переменные сборки (VITE_*)

> Status: **complete**
> Last exercised: _29.09.2026 — замер бандла пилота и локальная `vite build` (DRF-2654)_
> Owner: _тот, кто выкладывает dev / пилот_

## Purpose

Какие переменные мини-приложение читает **при сборке**, где их задают для
выкладки и что будет, если не задать. Значения `VITE_*` вшиваются в бандл при
`vite build`; после выкладки их не поменять без новой сборки.

## Переменные

| переменная | где читается | production | dev (`npm run dev`) |
|---|---|---|---|
| `VITE_SUPPORT_DEEPLINK` | `src/lib/customer-profile.ts` (`SUPPORT_DEEPLINK`) — ссылка «поддержка» в шторках личных данных | **обязательна**: не задана или пуста → сборка **отказывает** с её именем. До отказа в бандл вшивалась заглушка `https://max.me/aylasupport` — так собран пилот 29.09 | не обязательна: пусто → та же заглушка |
| `VITE_DEV_*` (`DEV_INIT_DATA`, `DEV_START_PARAM`, `DEV_BYPASS_USER_ID`, `DEV_BYPASS_TENANT_SLUG`) | `src/lib/max-sdk.ts`, `src/lib/dev-bypass.ts` | не используются: ветки срезаются, `import.meta.env.DEV === false` | локальный вход без MAX |
| `VITE_RECOMMENDATION_SHELF` | `src/lib/feature-flags.ts` | `"1"` — полка рекомендаций включена, иначе выключена | так же |

## Где задаётся для выкладки

- **Пилот / dev (`deploy-dev.yml`, шаг «Build Mini App on the runner»)** — из
  переменной репозитория GitHub (*Settings → Secrets and variables → Actions →
  Variables* → `VITE_SUPPORT_DEEPLINK`), **без заглушки**. Не задана → шаг
  сборки краснеет, и **новое мини-приложение на пилот не уезжает**, пока
  переменную не зададут. Задаёт её владелец: только он может назвать
  настоящий канал.
- **CI (`ci.yml`) и сверка дрейфа (`miniapp-drift.yml`)** — та же переменная, а
  если её нет, названная заглушка `https://example.invalid/...`. Эти бандлы
  людям не уезжают.
- На машине пилота мини-приложение **не собирают** (Node там нет; §2.6 и §4
  `server-deployment.md` — только для истории). Переменную на машине задавать
  незачем.

## Step-by-step procedure

1. Узнать у владельца настоящий адрес канала поддержки (вопрос в реестре).
2. Владелец задаёт `VITE_SUPPORT_DEEPLINK` в переменных Actions репозитория.
3. Запустить выкладку (`deploy-dev`).
4. Проверка на машине: в `apps/miniapp/dist/assets/*.js` есть заданный адрес и
   **нет** `max.me/aylasupport`:
   `grep -l '<адрес>' dist/assets/*.js` → ≥ 1 файл;
   `grep -l 'max.me/aylasupport' dist/assets/*.js` → 0 файлов.
5. Проверка глазами — смоук-шаг «Support-канал Mini App»
   (`pilot-deployment-part-3-smoke-tests.md`, prerequisites): кнопка «Написать
   в поддержку» открывает живой канал, а не 404.

## Если не задать

Выкладка краснеет на шаге сборки с текстом `DRF-2654: production build needs
VITE_SUPPORT_DEEPLINK`, и прогон `deploy-dev` красный. Порядок шагов важен:
бэкенд к этому моменту **уже выкачен** («Pull + rebuild + restart dev
services» идёт раньше сборки), а мини-приложение остаётся **прежним** — живой
`dist` не трогается. То есть на пилоте новый бэкенд и старый фронт, пока
переменную не зададут. Сам отказ задуман: умолчание из кода уже однажды
уехало в прод как настройка. Ослаблять отказ или возвращать умолчание нельзя;
выход один — задать переменную.
