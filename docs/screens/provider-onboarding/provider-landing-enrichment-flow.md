## 0. Назначение документа

`Provider Landing Enrichment Flow` описывает процесс умного приземления нового мастера или салона в Ayla.

Это не просто регистрация.

Это процесс, в котором Ayla помогает пользователю быстро создать рабочий профиль, используя данные из доступных источников:

- YCLIENTS;
- Яндекс.Карты;
- 2ГИС;
- VK;
- сайт;
- Telegram;
- загруженные прайсы;
- фото;
- PDF;
- Excel;
- другие публичные или подключённые источники.

Главная цель:

> Пользователь не заполняет профиль с нуля. Он подтверждает то, что Ayla уже нашла, собрала и структурировала.

Если внешних источников нет, Ayla не бросает пользователя в пустую анкету. Она предлагает стартовый профессиональный шаблон по специализации: маникюр, массаж, брови, ресницы, эпиляция, косметология, парикмахерские услуги и другие направления.

## 1. Проблема

Обычная регистрация мастера или салона выглядит тяжело:

```text
Заполните название.
Заполните адрес.
Добавьте телефон.
Добавьте описание.
Добавьте услуги.
Добавьте цены.
Добавьте длительности.
Добавьте мастеров.
Загрузите фото.
Настройте расписание.
Проверьте всё вручную.
```

Для малого бизнеса это барьер.

Мастер или владелец салона часто думает:

```text
“Мне некогда всё это заполнять.”
“У нас уже всё есть в YCLIENTS.”
“У нас всё есть в VK.”
“У нас есть прайс в картинке.”
“У нас карточка в Яндекс.Картах уже заполнена.”
```

Если Ayla заставляет заполнять всё заново, она воспринимается как очередная CRM.

Если Ayla сама собирает данные и предлагает готовый черновик, она воспринимается как умный помощник.

---

## 2. Продуктовая цель

Создать эффект:

```text
“Я ввёл только название или ссылку, а Ayla уже собрала мой профиль.”
```

или, если источников нет:

```text
“У меня ещё нет сайта и соцсетей, но Ayla всё равно помогла стартовать по готовому шаблону.”
```

Пользователь должен увидеть:

```text
название
адрес
телефон
описание
услуги
цены
длительности
мастеров
расписание
фото
ссылки
источники
```

И дальше не заполнять всё вручную, а принимать решения:

```text
[Принять]
[Изменить]
[Не использовать]
```

---

## 3. Главный принцип

Ayla не должна автоматически публиковать найденные данные.

Правильная цепочка:

```text
найти
→ собрать
→ нормализовать
→ показать пользователю
→ получить подтверждение
→ создать черновики сущностей
→ пройти go-live checklist
→ опубликовать
```

Все найденные данные сначала являются черновиком.

---

## 4. Ключевая продуктовая формула

```text
Smart Landing = минимальный ввод + поиск источников + извлечение данных + template fallback + AI-нормализация + human review + bootstrap
```

Где:

- **минимальный ввод** — пользователь вводит название, телефон или ссылку;
- **поиск источников** — Ayla ищет YCLIENTS, Яндекс.Карты, 2ГИС, VK, сайт и другие источники;
- **извлечение данных** — Ayla вытаскивает контакты, услуги, цены, фото, расписание;
- **template fallback** — если источников нет, Ayla создаёт стартовый профиль по шаблону специализации;
- **AI-нормализация** — Ayla приводит данные к структуре Ayla;
- **human review** — пользователь подтверждает данные;
- **bootstrap** — система создаёт tenant, профиль, услуги, расписание и связи.

## 5. Основные сценарии

### 5.1. Solo-мастер

Ольга открывает Ayla Pro.

Ayla спрашивает:

```text
Введите имя, телефон, название профиля или ссылку на страницу, где есть информация о вас.
```

Ольга вводит:

```text
Ольга массаж Пенза
```

или вставляет ссылку:

```text
https://vk.com/...
https://yclients.com/...
ссылка на Яндекс.Карты
ссылка на 2ГИС
сайт
```

Ayla отвечает:

```text
Я нашла данные о вас в нескольких источниках.
Собрала черновик профиля. Проверьте, что можно использовать.
```

После подтверждения создаётся:

```text
tenant type = solo_provider
BotUser
roles = owner + admin + master
Provider profile
Services
WorkingHours
Photos
Provider notifications
Draft customer-facing profile
```

---

### 5.2. Салон

Владелец или администратор вводит:

```text
Формула тела Пенза
```

Ayla находит:

```text
Яндекс.Карты
2ГИС
VK
сайт
YCLIENTS
фото
услуги
адрес
телефон
часы работы
```

Ayla показывает:

```text
Я собрала черновик салона.

Готово:
✓ название
✓ адрес
✓ телефон
✓ 14 услуг
✓ 28 фото
✓ часы работы

Нужно проверить:
⚠ 3 услуги без длительности
⚠ разные часы работы в источниках
⚠ 2 фото нужно подтвердить
```

После подтверждения создаётся:

```text
tenant type = salon
Owner/Admin membership
Salon profile
Master profiles
Services
Master-service mapping
WorkingHours
Branch/location
Photos
Provider notifications
Draft customer-facing profile
```

---

### 5.3. Пользователь даёт ссылку на YCLIENTS

Если пользователь вставляет ссылку на YCLIENTS, Ayla должна сначала попробовать получить наиболее структурированные данные:

```text
услуги
цены
длительности
мастера
филиалы
расписание
онлайн-запись
```

YCLIENTS — потенциально самый ценный источник, потому что там часто уже есть структура бизнеса.

Но важно:

```text
если нет официального доступа/API/токена, не обещать полный импорт;
если доступ ограничен, показать, что удалось получить;
если нужно подключение, попросить пользователя авторизоваться или добавить другой источник.
```

---

### 5.4. Пользователь загружает прайс

Если пользователь не хочет искать источники, он может загрузить:

```text
PDF
Excel
фото прайса
скриншот
текстовый файл
```

Ayla должна распознать:

```text
названия услуг
цены
длительности
категории
абонементы
пакеты
скидки
```

И создать черновики услуг.


### 5.5. Пользователь без цифрового следа

Подключается новый solo-мастер:

```text
Мария
Маникюр и педикюр
Пенза
Нет сайта
Нет VK
Нет YCLIENTS
Нет Яндекс.Карт
Нет 2ГИС
```

Плохой UX:

```text
Ничего не найдено. Заполните всё вручную.
```

Правильный UX:

```text
Я пока не нашла ваш профиль в открытых источниках.

Могу быстро подготовить стартовый профиль по шаблону мастера маникюра и педикюра:
- базовые услуги;
- типовые длительности;
- рекомендованные диапазоны цен по региону;
- описание профиля;
- расписание по умолчанию;
- подсказки, что проверить перед публикацией.

[Создать по шаблону]
[Загрузить прайс]
[Заполнить вручную]
```

После выбора шаблона Ayla создаёт черновик, а пользователь проверяет и меняет цены, длительности, список услуг и расписание.

## 6. Общая схема процесса

Процесс состоит из 12 этапов:

```text
0. Согласие пользователя
1. Минимальный ввод
2. Поиск источников
3. Подтверждение найденного бизнеса
4. Сбор данных
5. Template fallback, если источников нет или confidence низкий
6. Нормализация данных
7. Слияние и дедупликация
8. Confidence score и конфликты
9. AI-обогащение
10. Проверка пользователем
11. Создание черновика профиля
12. Bootstrap в Ayla
13. Go-live checklist
```

# Этап 0. Согласие пользователя

## Зачем нужно

Ayla собирает данные из внешних источников. Даже если часть данных публичная, пользователь должен понимать, что происходит.

Нужно честно объяснить:

```text
Я могу помочь собрать черновик профиля из открытых и подключённых источников.
Перед публикацией вы всё проверите и подтвердите.
```

## Что пользователь подтверждает

Пользователь должен понять и подтвердить:

```text
Ayla может искать информацию по введённому названию, телефону или ссылке.
Ayla может использовать найденные данные только как черновик.
Публикация будет только после подтверждения.
Пользователь отвечает за право использовать фото, тексты и материалы.
```

## UX-текст

```text
Я помогу собрать ваш профиль быстрее.

Могу поискать данные в открытых и подключённых источниках: карты, сайт, соцсети, прайс, YCLIENTS и другие.

Перед публикацией вы всё проверите и подтвердите.

[Начать]
```

## Нельзя

```text
Я всё соберу и опубликую автоматически.
```

## Нужно

```text
Я соберу черновик. Вы всё проверите перед публикацией.
```

```text

```

```text

   Пенза, ул. ...
```


# Этап 5. Template fallback — запуск по шаблону

## Зачем нужен

Не у каждого нового мастера есть сайт, YCLIENTS, соцсети или карточки на картах.

Особенно это касается:

```text
начинающих solo-мастеров
мастеров, которые раньше работали только по сарафану
мастеров на дому
мастеров, которые только переезжают в кабинет
специалистов, которые ведут записи в блокноте или мессенджере
```

Если источников нет, Ayla всё равно должна помочь начать.

Главная идея:

> Если нечего парсить, Ayla создаёт стартовый черновик по профессиональному шаблону.

---

## Когда включать template fallback

Template fallback запускается, если:

```text
источники не найдены
источники найдены, но confidence низкий
найдены только неполные данные
пользователь сам выбирает “Создать по шаблону”
```

## Региональные цены

Ayla может предлагать не точные цены, а рекомендованные диапазоны.

Правильно:

```text

Какую цену поставить?
[1 500 ₽]
[1 800 ₽]
[2 000 ₽]
[Ввести свою]
```

Неправильно:

```text
Мы поставили вам цену 1 800 ₽.
```

Цены должны быть:

```text
рекомендованные
черновые
требующие подтверждения
```

## Откуда брать региональные цены

Источники для `RegionPriceBenchmark`:

```text
ручные seed-данные на старте
публичные прайсы салонов и мастеров
исследование рынка по городу
накопленная база Ayla после запуска
подключённые структурные источники, если это разрешено условиями
```

Для MVP не нужно строить сложный парсинг рынка.

Рекомендуемый MVP-подход:

```text
template base price
+ region coefficient
+ price level: economy / medium / premium
```

Пример:

```text
base_template = nail_master_solo
region = Penza
price_level = medium
```

Результат:

```text
Маникюр с покрытием: 1 500–2 300 ₽
Педикюр с покрытием: 2 000–3 200 ₽
```

# Этап 8. Confidence score и конфликты

## Что такое confidence score

Это уровень уверенности Ayla в найденном поле.

Пример:

```text
Телефон найден в 3 источниках — высокая уверенность.
Часы работы отличаются — конфликт.
Цена услуги есть только на старом посте VK — низкая уверенность.
```

## Уровни

```text
high — можно предложить к подтверждению как почти готовое
medium — нужно показать источник и попросить проверить
low — лучше оставить как подсказку
conflict — пользователь должен выбрать правильный вариант
```

## Пример конфликта

```text
Часы работы отличаются:

Яндекс.Карты: 10:00–20:00
2ГИС: 10:00–19:00
Сайт: по записи

Что использовать?
[10:00–20:00]
[10:00–19:00]
[По записи]
[Заполнить вручную]
```

## Правило

Если есть конфликт, Ayla не должна молча выбирать.

# Этап 9. AI-обогащение

## Зачем нужно

Сырые данные часто плохо выглядят.

Например, из источников нашли:

```text
Массаж спины, 2500, 60 мин
```

Ayla может предложить красивое описание:

```text
Массаж спины — процедура для снятия мышечного напряжения и ощущения лёгкости после нагрузки. Подходит тем, кто много сидит, тренируется или чувствует усталость в спине.
```

Но важно: AI-текст — только черновик.

## Что может делать AI

```text
улучшить описание профиля
структурировать услуги
предложить категории
предложить короткое описание мастера
предложить подготовку к услуге
выделить преимущества
сделать текст спокойным и доверительным
```

## Что AI не должен делать

```text
обещать лечение
ставить диагнозы
копировать чужие отзывы
выдумывать услуги
выдумывать цены
выдумывать расписание
публиковать без подтверждения
```

## Safety-примеры

Нельзя:

```text
лечит грыжу
гарантирует похудение
избавляет от целлюлита навсегда
устраняет диагноз
```

Можно:

```text
помогает расслабиться
может подойти тем, кто чувствует мышечное напряжение
направлено на ощущение лёгкости и восстановления
```

# 18. Правила безопасности

## Нельзя

```text
публиковать найденные данные без подтверждения
копировать чужие фото без права использования
копировать отзывы как собственный текст
выдумывать цены
выдумывать мастеров
выдумывать расписание
обещать медицинский эффект
использовать неподтверждённые данные как final
публиковать шаблонные цены без подтверждения
выдавать региональный benchmark за точную рыночную цену
```

## Нужно

```text
хранить источник каждого поля
показывать конфликты
давать кнопку “не использовать”
получать подтверждение перед публикацией
проверять медицинские обещания
разделять публичные и внутренние данные
сохранять audit trail
помечать template-generated fields как requires_review
```

# 19. Privacy / legal guardrails

## Consent

Перед поиском пользователь должен согласиться:

```text
Ayla поможет собрать черновик профиля из открытых и подключённых источников.
Перед публикацией вы всё проверите.
```

## Provenance

Каждое важное поле должно хранить источник:

```text
откуда взято
когда получено
с какой уверенностью
подтвердил ли пользователь
```

## Фото

Фото нельзя публиковать без подтверждения.

UX:

```text
Подтвердите, что вы можете использовать эти фото в профиле.
```

## Отзывы

Отзывы нельзя копировать как свои тексты.

Можно использовать:

```text
суммарные инсайты
частые плюсы
частые темы
```

## Медицинские обещания

Тексты услуг должны проходить safety-check.

## 2. Источники конфликтуют

Решение:

```text

дать выбрать актуальный
```

Решение:

```text

предложить загрузить прайс

```

---

## 4. Услуги найдены, но без цен

Решение:

```text
создать черновики услуг
пометить “нужно указать цену”
не публиковать
```

---

## 5. Услуги найдены, но без длительности

Решение:

```text
создать черновики
предложить типовые длительности
не делать bookable до подтверждения
```

---

## 6. Фото найдены, но права непонятны

Решение:

```text
показать фото
попросить подтвердить право использования
не публиковать автоматически
```

Решение:

```text

```

## 8. Салон с несколькими филиалами

Решение:

```text
создать branch candidates
попросить выбрать филиал
не смешивать расписания и услуги разных филиалов
```

Решение:

```text

не создавать solo-provider автоматически без подтверждения
```

---

## 10. Найдены старые цены

Решение:

```text
пометить как low confidence
показать источник и дату
попросить подтвердить
```

```text
создать стартовый профиль
попросить проверить цены/услуги/расписание
```

## 12. Шаблонные цены не подходят мастеру

Решение:

```text
дать быстрый выбор “ввести свою цену”
не публиковать benchmark без подтверждения
сохранить исправленное значение как user-confirmed
```

## 13. Шаблон создал лишние услуги

Решение:

```text
дать bulk reject / hide
не делать все услуги visible автоматически
публиковать только подтверждённые
```

# 23. Acceptance criteria

1. Пользователь может начать приземление с названия, телефона или ссылки.
2. Ayla находит несколько возможных источников.
3. Пользователь может выбрать, какие источники использовать.
4. Ayla создаёт черновик профиля.
5. У каждого поля есть источник.
6. У каждого важного поля есть confidence.
7. Конфликтные поля требуют подтверждения.
8. Услуги создаются как draft, если не хватает цены/длительности.
9. Фото не публикуются без подтверждения.
10. AI-описания не публикуются без подтверждения.
11. После review можно создать tenant/profile/services/schedule.
12. Solo-provider получает роли owner/admin/master.
13. Salon получает tenant, owner/admin и черновики мастеров.
14. Перед публикацией проходит go-live checklist.
15. Пользователь видит прогресс готовности профиля.
16. Система не публикует неподтверждённые данные.
17. Все созданные данные сохраняют provenance.
18. Ошибки источников не ломают весь процесс.
19. Можно продолжить вручную, если enrichment не сработал.
20. После bootstrap можно пройти тестовую запись.
21. Multi-source conflicts отображаются пользователю.
22. User can reject any found field/source.
23. Uploaded price file can create service drafts.
24. Provider landing session can be resumed later.
25. Audit trail exists for accepted/rejected fields.
26. If no sources are found, user can start with template-based bootstrap.
27. Template-generated services are created as draft/requires_review.
28. Region price benchmarks are displayed as recommendations, not final prices.
29. User can change or reject any template-generated service.
30. Template flow can create a usable solo-provider draft without external sources.

# 24. Definition of Done

Модуль `Provider Landing Enrichment` считается готовым, если новый мастер или салон может:

```text
ввести название или ссылку
увидеть найденные источники
или выбрать запуск по шаблону, если источников нет
подтвердить свой бизнес или специализацию
получить черновик профиля
проверить услуги, фото, контакты и расписание
исправить конфликты
создать профиль в Ayla
запустить тестовую запись
```

Главный критерий:

> Пользователь не заполняет профиль с нуля. Он подтверждает то, что Ayla уже собрала.
