# Окно W2 — мастер не может войти и не узнаёт о брони

Ты главное окно этого потока. Работай своими сабагентами, если нужно.

## Зачем поток

Мастер — третья сторона контура, и она сегодня не работает целиком: войти нельзя, а если вошёл — о записях не узнаёшь.

## Задачи

```
DRF-1080  приглашённый мастер приезжает с is_active=False и ловит 403   2 SP
DRF-1081  /onboarding/master недостижим для того, кто ещё не мастер      2 SP
DRF-1079  SITE_DOMAIN на пилоте не задан — фолбэк ведёт на localhost     1 SP
DRF-1030  все push специалисту падают: «no tokens», устройств нет        3 SP
```

Все четыре — **блокеры пилота** по критерию владельца.

**DRF-1081 — логическая петля:** единственный вход в состояние требует, чтобы состояние уже наступило. Смонтирован только при уже истинном `hasMaster`.

**DRF-1080 рядом:** приём приглашения не выставляет `is_active`, при этом роль мастера уже истинна — 403 на всех мастерских эндпоинтах **без объяснения причины**.

**DRF-1030 требует осторожности.** Закрытая DRF-1069 называет её «уже выложенной» и чинит дыру в ней. То есть уведомление салона, скорее всего, работает, а нерешённым остался **специалист**, чей единственный канал — FCM в мобильное приложение при нуле устройств. **Первый шаг — установить, что уже работает**, и переформулировать задачу, если объём в ней меньше заголовка.

## Территория

Твоя: `apps/master_api/**` кроме `services/schedule.py`, `apps/admin_api/views_invite.py`, `apps/notifications/**`, настройки `SITE_DOMAIN`.

**Занято — не входить:**

```
apps/master_api/services/schedule.py              салонный бэкенд (окно C)
appointments/views.py в бэкенде Ayla              салонный бэкенд (окно C)
apps/channels/max/global_onboarding.py            первый экран
apps/orchestrator/discovery.py, handoff.py        воронка записи
apps/skills/booking/                              воронка записи
apps/skills/health_screening/classifier.py        распознавание намерений
apps/orchestrator/fast_path.py                    заморожено
```

`apps/notifications/proactive.py` — там же лежит гейт «бот пишет первым» из DRF-1307. **Не ослаблять его.** Есть открытая задача DRF-1338 на расширение этого гейта до двух согласий; не делай её заодно, она не твоя.

## Правила

Своё дерево от свежего `origin/dev`, в чужие не входить. PR против `dev`. Мержит владелец.

**Телефон клиента исполнителю не передаётся** — решение владельца DRF-1039. Это касается тебя напрямую: мастерские поверхности соблазнительно снабдить телефоном.

Секреты не печатать. §0-ter про откатываемые транзакции. `cancelled` ≠ падение.

Опровержение постановки ценнее согласия — с `файл:строка`.
