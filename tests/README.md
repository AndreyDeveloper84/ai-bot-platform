# Как читать вывод прогона

## Итоговой строки здесь нет

`pytest` в этом репозитории **не печатает** привычную последнюю строку
(`5 passed, 1 skipped in 12.34s`). В выводе остаются только точки прогресса,
сводка предупреждений и ссылка на документацию — так складывается набор
плагинов из `addopts` (`pyproject.toml`, `[tool.pytest.ini_options]`).

Практическое следствие: под `tail` (а прогон обычно смотрят через `| tail -20`)
добываемо **только отсутствие красного**, но не количество. «Красных строк не
было» и «прошло N узлов» — разные утверждения, и второе таким способом не
получить. Называть число, которого не видел, нельзя: это выдуманный факт в
отчёте, а не округление.

## Как всё-таки получить число

Считать символы прогресса:

```bash
pytest apps/<app>/tests -q > out.txt 2>&1
grep -oE "^[.sxFE]+" out.txt | tr -d '\n' | wc -c          # сколько узлов прошло всего
grep -oE "^[.sxFE]+" out.txt | tr -d '\n' | fold -w1 | sort | uniq -c
```

Второй вызов ценнее первого: он раскладывает прогон по символам и показывает не
только точки, но и пропуски (`s`), ожидаемые падения (`x`), падения (`F`) и
ошибки (`E`). Прогон, где «нет FAILED», и прогон, где половина узлов `s`, под
`tail` выглядят одинаково.

## Отчёт

Если число прогона идёт в тело PR или в отчёт человеку — называть рядом,
откуда оно взято («счёт по точкам прогресса: итоговую строку прогон не
печатает»). Тогда читающий знает, что именно измерено.
