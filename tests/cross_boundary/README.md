# Cross-boundary golden — бот ↔ каталог по настоящему HTTP

**Если здесь покраснел P1 — прочтите это до того, как чинить стенд.** P1 («прямая услуга →
бронь») в матрице готовности стоит как PARTIAL с формулировкой «цена/длительность подменяются
молча». Golden P1 проверяет «бот показал X — каталог записал X» и **обязан** краснеть ровно там.
Красный P1 — находка о продукте, а не поломка стенда; стенд отвечает за пульс (`test_pulse.py`),
и если пульс зелёный, а P1 красный — стенд исправен.

## Что это и чем отличается от всего остального

Единственный уровень тестов, где бот и каталог — **два процесса, соединённые HTTP**, оба на
известных SHA. Всё остальное этого не делает:

* replay golden/adversarial — TCP закрыт `NetworkTripwire`'ом, фикстура, дошедшая до каталога,
  «не проверена ничем»;
* контрактный маршрутный лист — что бот **зовёт**, не что каталог **отвечает**;
* `tests/e2e/test_ayla_integration.py` — против живого пилота, недетерминирован, в CI пропущен
  целиком, если `AYLA_BASE_URL` пуст. Пропуск и есть то, чего здесь нет: см. ниже.

План и замер — `docs/PLAN_CROSS_BOUNDARY_GOLDEN.md` (способность 41 матрицы, `CROSS_BOUNDARY 0`).

## Стенд не поднялся ≠ зелёный

В этом каталоге **нет `skipif`**. Нет стенда — тесты **падают** с названной причиной. Пропуск
модуля целиком даёт зелёный job с нулём тестов, и именно так сегодня устроен `test_ayla_integration`.

Три способа не подняться, и что их ловит:

```
каталог не собрался              шаг сборки в workflow — очевидно
собрался, но не мигрировал       пульс читает /api/v1/health/ready/ и требует
                                 checks.migrations.ok — healthcheck контейнера этого не видит
поднялся, бот его не увидел      переменные не выставлены → conftest ПАДАЕТ, не пропускает
```

Плюс junit: `tests == 0` — отказ (#1544).

## Как запустить

Стенд — каталог `beautygo_backend` на **пустой** базе, с сервисным токеном:

```
# каталог (второй репозиторий), своя база, тестовые настройки — без MinIO и Redis
DJANGO_SETTINGS_MODULE=djangoProject.settings.test POSTGRES_DB=golden_local \
AYLA_INTERNAL_API_TOKEN=golden-token \
  python manage.py migrate --noinput && python manage.py runserver 127.0.0.1:8091

# бот
CROSS_BOUNDARY_CATALOG_URL=http://127.0.0.1:8091 \
CROSS_BOUNDARY_CATALOG_TOKEN=golden-token \
CROSS_BOUNDARY_CATALOG_SHA=$(git -C ../beautygo_backend rev-parse HEAD) \
  uv run pytest tests/cross_boundary -m cross_boundary -v
```

Имена переменных **нарочно не** `AYLA_BASE_URL`: чтобы обычный прогон нельзя было случайно
направить в каталог, а этот — случайно в пилот.

Из обычного прогона каталог исключён маркером (`-m "not smoke and not cross_boundary"` в
`pyproject.toml`); стендовый job запускает его явно с `-m cross_boundary`.

## Сценарии

| файл | что доказывает | посев каталога |
|---|---|---|
| `test_pulse.py` | стенд жив: readiness с `db.ok` и `migrations.ok`; SHA каталога напечатан рядом; проверенный клиент **создаётся на лету** (proxy) — посев клиента не нужен | нет |
| `test_p7_no_verified_candidates.py` | отсутствие доезжает отсутствием **с именем**: три слоя ответа, у каждого своё «пусто» | пустой каталог (P7-a); мастера без VERIFIED-маппинга (P7-b, `seed_golden --scenario p7`) |

Два «пусто» у P7 — **разные**, и golden их различает, потому что каталог их различает:

```
пустой каталог                 layer_2.reason_codes == ["QUALITY_NO_EVIDENCE"]
                                  — свидетельств нет вовсе
мастера есть, VERIFIED нет     layer_2.reason_codes ∋ "ELIG_EXCLUDED_NOT_RECOMMENDABLE"
                                  — каталог видно, рекомендовать нечего: состояние ПИЛОТА
layer_1 всегда                 items == [], reason_codes == [] — решения не принимали:
                                  истории у нового клиента нет
```

Коды названы **по факту ответа стенда 11.09.2026**, не по чтению кода.

## Что здесь НЕ проверяется — названо

* Реплика бота человеку. Golden уровня клиента: что каталог отвечает боту. Поверхность
  (текст ответа) — отдельный слой, он на боте детерминирован и покрыт replay.
* Версия каталога. `/health/ready/` отдаёт статичное `version: 1.0.0`; SHA берётся из
  переменной workflow и печатается пульсом. Каталог, отдающий свой SHA, — отдельная строка.
